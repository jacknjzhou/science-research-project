## 1. 范围与依赖

本模块管理科研院所所有参与科研活动的人员档案与团队结构（正式研究人员/博士后/访问学者/客座/研究生/临时聘用），核心目标是把"孤立档案"升级为**与项目、经费、成果深度关联的科研画像实体**（PI 画像自动化、跨机构流动 0 断档）。

## 2. 服务与分层

微服务划分（一模块一库，跨库只存对方 `id`，一致性走 Kafka 事件；见 `../TECH_ARCHITECTURE.md` §八）：

```
svc-staff（S 主服务）
├─ interfaces  : REST（07-...openapi.yaml）/ DTO / Assembler / 脱敏序列化
├─ application : 档案 CRUD、团队增删成员编排、客座申请-审批-开通、异动状态机、幂等、对账触发
├─ domain      : S_STAFF 聚合根 + S_TEAM/S_MEMBERSHIP/S_VISITOR/S_STUDENT/S_TALENT_PLAN 实体
│                规则策略（双主键去重、双聘主部门唯一、异动交接、权限到期）
└─ infra       : PG(15) 仓储、Kafka 生产/消费、加密列读写（id_card/bank）、对象存储头像/附件

svc-mdm（主数据）
└─ 提供 sys_dict（岗位/职称/计划/评估周期可配）、sys_org（部门树）、sys_role（角色）读取

svc-integration-hr / cas-ldap / orcid（外部同步管道）
├─ hr          : 北森/SAP/用友 → 增量拉取 + 变更推送 → 落 S_STAFF 基本信息（S-01）
├─ cas-ldap    : 单点登录 / 账号开通（客座审批后建 sys_user）
├─ orcid       : ORCID API 拉取学者成果与标识，回填外部标识 + 去重佐证
└─ reconcile   : 定时对账（人事未同步检测）+ 手动纠错入口（§4.6）

svc-profile（画像引擎，被 svc-staff 调用 / 独立批处理）
├─ aggregate   : S_PORTRAIT 聚合（项目/经费/成果/引用/合作/诚信六维），周批 + 事件即时
├─ collab      : S_COLLAB_GRAPH 共现聚合（论文/项目/专利）+ 中心度 + 社团检测
└─ snapshot    : 日/周切片落库（幂等，staff_id+snapshot_date 唯一）

svc-ai-gateway（AI 中台）
├─ expertise   : LLM 方向标签生成（S-05，对齐 arXiv/中图分类）
├─ summary     : LLM 画像自然语言摘要（S-13）、AI 简历生成
└─ gap         : 人才梯队缺口（模型 + 规则混合，S-15）
```

分层约束：`interfaces` 不触库；`domain` 不依赖框架；`infra` 实现仓储与适配器；跨模块联动（PI 交接触发 E/F、画像回流 D 大屏、承诺触发 C）一律通过事件解耦。**敏感列读写仅在 `infra` 加密组件完成，`domain` 只见脱敏视图或密文引用。**

## 4. 关键业务规则

### 4.1 人员异动流程与 PI 离职项目交接 / 经费冻结联动（S-10）

异动动作 `RESIGN/RETIRE/TRANSFER_DEPT/REHIRE/LEAVE`（`POST /staff/{id}/transfer`），状态机（employment_status）：

```
ONBOARD ──RESIGN──▶ RESIGNED      （离职，触发交接判定）
ONBOARD ──RETIRE──▶ RETIRED       （退休，同上；可转 REHIRE 返聘）
ONBOARD ──TRANSFER_DEPT──▶ ONBOARD（部门变更，主 department_id 改写，次部门进 secondary_dept_ids）
RETIRED ──REHIRE──▶ REHIRE        （返聘，权限按新身份，§8）
VISITING/GUEST ──到期──▶ RESIGNED （客座到期自然失效，§4.2）
```

**PI 离职/退休强制交接（S-USR-03，核心联动）**：
1. 若 `is_pi=true` 且 `action ∈ {RESIGN,RETIRE}`，接口**强校验 `handover_pi_staff_id` 必填**，否则拒绝归档（HTTP 400，业务码 `S_PI_HANDOVER_REQUIRED`）。
2. 事务内：S_STAFF.employment_status→RESIGNED/RETIRED、status→INACTIVE（档案保留可查不可编辑）。
3. 发 `staff.pi_left` 事件 → **触发 E 项目交接**：其名下在研 `E_PROJECT` 状态进入交接流程，PI 由 `handover_pi_staff_id` 承接或转管理代收。
4. **经费冻结（触发 F）**：交接完成前，`F_BUDGET`/报销受理置冻结（新报销/外拨进入 `HUMAN_REVIEW` 或阻断），交接完成→移交，由 F 模块执行；S 侧只发事件不做金额裁决（跨微服务库，一致性走事件）。
5. 团队/学生改派：其 LEADER 团队 `status→CHANGING`，导师 `supervisor_staff_id` 待改派队列；权限降级为"离职可见本人"（sys_user.status→DISABLED，角色 revoke）。
6. 归档保留（§9，离职档案 15 年）。

非 PI：跳过 3/4，仅权限降级 + 团队/学生无强制改派 → 归档。

### 4.2 客座/访问学者短期权限生命周期（S-11，到期自动失效）

入驻 → 审批 → 开通账号 → 分配权限范围 → 到期前提醒 → 到期自动失效：

- **申请（APPLIED）**：`POST /visitors`，携 host_pi、期限 start/end、`permissions_scope`（限本项目/本团队）。
- **审批（APPROVE）**：`POST /visitors/{id}/approve` → 建 sys_user + S_STAFF(staff_type=VISITING_SCHOLAR/GUEST) → 按 `permissions_scope.role_codes` 写 `sys_user_role`，**关键：`sys_user_role.expires_at = S_VISITOR.end_date`**（00-common 已具备该列）。status→ACTIVE。
- **提醒**：调度每日扫 `idx_visitor_end`，在到期前 **30 / 7 天** 置 `reminder_stage=DUE_30/DUE_7`（幂等，避免重复推送）。
- **到期自动失效（100%）**：到达 `end_date` 时，调度规则将 S_VISITOR.status→EXPIRED、employment_status→RESIGNED，并 **revoke sys_user_role**（`expires_at` 到期后 RBAC 校验即失效 + 显式删除授权），发 `staff.permissions.expired`。权限降级"仅可见本人历史"。
- **提前终止**：TERMINATED（人工/违规），同 revoke。

> 与 `sys_user_role.expires_at` 协作：`expires_at` 是**权限层到期权威**（校验时 `expires_at > now()`），S_VISITOR.end_date 是**业务层到期**；两者同值，失效由调度规则触发事件保证最终一致（双重保障，验收 100%）。

### 4.3 同名学者"工号 + ORCID 双主键"去重（PRD §11）

- 院内同名同姓：以 `hr_code`（工号）唯一 + `orcid` 唯一 **双主键**判定身份；仅姓名命中不视为同一人。
- 匹配口径：院内建档 `uk_staff_hrcode (tenant_id,hr_code)`、`uk_staff_orcid (orcid) WHERE orcid IS NOT NULL`；跨模块（成果认领、画像聚合）比对先 ORCID，再工号，二者任一冲突即隔离为不同实体并进人工复核队列。
- 外部同步：ORCID API 拉取佐证外部标识；缺 ORCID 时以工号为准并标注 `source=MANUAL` 待补。

### 4.4 双聘 / 一人多部门，主部门唯一（PRD §11）

- **主部门唯一**：`S_STAFF.department_id` 单值，绩效/统计/隔离以主部门为准。
- **多部门**：`secondary_dept_ids` JSONB `[{org_id,effort_pct}]` 记录兼聘部门与投入占比（跨部门贡献可分配，effort_pct 之和建议 ≤ 1）。
- 团队/项目成员资格独立于部门（S_MEMBERSHIP），双聘者可同时参与多部门团队；画像聚合默认按主部门，可指定按 effort 分摊（联动 F/G 成本归属）。

### 4.5 S-13 PI 画像聚合口径（周批 + 事件即时）

聚合数据源：**项目（E）+ 经费（F）+ 成果（R）+ 引用（R_METRIC_SNAPSHOT）+ 合作（S_COLLAB_GRAPH）+ 培养（S_STUDENT）+ 诚信（C，M2）**。

- **口径**：
  - project_count_*：主持（PI）与参与分别计，"在研"取 E_PROJECT 状态 EXECUTING/MID_CHECK/DELAYED。
  - funding_total/yearly：NUMERIC(18,2) 元，取 F 到账/立项口径（不含外拨转出的代收）。
  - output_count_*：R_OUTPUT 中 CLAIMED 且归属本人（作者份额）的论文/专利。
  - h_index/total_citations：基于当日 R_METRIC_SNAPSHOT 全作者序列计算 h 指数。
  - collaboration_score：S_COLLAB_GRAPH 中心度归一；mentoring_count：在读 + 累计毕业。
- **更新节奏**：**每周批量刷新** 全院画像（svc-profile 批，见 §9 性能 < 30 min @ 5000 人）；**关键事件即时更新**：`output.claimed`、项目立项、新称号（S_TALENT_PLAN 写入）触发该学者单条重算，产 `staff.portrait.updated`（→ D 大屏）。
- **AI 摘要**：LLM 基于聚合数值生成自然语言学者简介（辅助评审/合作决策），`ai_summary` 落快照；数值口径以规则/聚合为准，摘要仅解释不裁决。
- 快照 `uk_portrait_day` 保证同 (staff_id,snapshot_date) 幂等；历史切片供时间轴。

### 4.6 S-14 合作关系网络构建（共现聚合 + 中心度 / 社团检测）

- **共现来源**：论文作者共现（R_OUTPUT.authors）、项目成员共现（E_PROJECT 成员）、专利发明人共现（R_PATENT_EXT.inventors）。
- **聚合**：两两学者配对，`weight` = 论文+项目+专利共现次数（可按类型加权），记 `first_year/last_year`、`shared_projects/shared_papers`。
- **无向边规范化**：`CHECK (staff_a_id < staff_b_id)`，`(a,b,snapshot_date)` 唯一。
- **分析**：度中心性/介数中心性 → `centrality_score`；社团检测（如 Louvain）→ `community_id`；跨机构桥接者识别（外部学者不入本院主表，作为虚节点或经 EXPERT 关联，见 §8）。
- **渲染约束**：按中心学者取 ego 网络，节点上限 **2000**；`min_weight` 边过滤降噪；`snapshot_date / from_year / to_year` 时间切片（§9）。

### 4.7 规则引擎 vs LLM 分工

| 能力 | 实现方 | 说明 |
|------|--------|------|
| 权限到期自动失效（S-11） | **调度规则** | `expires_at`/`end_date` 到点 revoke，确定性，绝不用 LLM |
| 人员异动交接 / 经费冻结（S-10） | **状态机 + 规则 + 事件** | is_pi 判据强制校验；金额裁决归 F |
| 双主键去重（S-04） | **规则** | 工号+ORCID 精确判定；模糊姓名→人工 |
| 研究方向标签（S-05） | **LLM** | 论文/专利文本抽关键词，对齐 arXiv/中图分类；软标签可复核 |
| 画像摘要 / AI 简历（S-13） | **LLM** | 自然语言生成，不改数值口径 |
| career_stage 阶段判定 | **规则 + 模型混合** | 阈值规则（年限/引用）为主，模型辅助，最终规则落 token |
| 人才梯队缺口（S-15） | **模型 + 规则** | 画像+退休时间表+战略方向→模型出分布/缺口，规则约束招聘建议 |
| 画像数值聚合（S-13） | **聚合管道（确定性）** | 数值由 SQL 聚合，可复算；LLM 不参与数值 |

原则：**确定性（数值聚合/权限到期/状态裁决）交管道与规则引擎；模糊判断（标签/摘要/预测）交 LLM；价值裁决（交接/经费/梯队建议）交规则 + 人工**。

## 7. 权限与隔离

在 PRD §9 权限矩阵（本人 / 团队负责人 / R-MANAGER / R-LEADER / HR / R-ADMIN）基础上补充可见性与密级规则：

- **编辑个人基本信息**：仅本人 + HR；**编辑科研专属字段**：本人（HR 为 R 部分可编）；**编辑他人档案 / 处理离职交接**：仅 R-MANAGER + HR（`PUT /staff/{id}`、`POST /staff/{id}/transfer` 非授权角色 `403`）。
- **团队增删成员 / 客座审批**：团队负责人 + R-MANAGER。
- **敏感字段**（id_card_hash / bank_card_hash / 家庭住址 / 绩效金额）：**非 HR/R-ADMIN 完全不可见**；序列化层脱敏（身份证 `1101**********1234`，银行卡不回显）；HR/管理员可见密文引用并**每次访问写 `sys_audit_log`**（action=EXPORT/READ，object_type=S_STAFF）。
- **失信档案 / integrity_flag**：仅**纪检（R-ETHICS）+ 管理员**可见；画像接口对普通角色过滤 `integrity_flag`，越权 `403`（PRD §9 查看他人失信档案=纪检）。
- **联系方式**：同院所（同 tenant/legal_entity）内可读（PRD §9 R 列）。
- **数据隔离**：所有查询强制注入 `tenant_id`（总院法人边界）+ `legal_entity_id`（法人细分）；主路径 `(tenant_id, legal_entity_id, status)` 组合索引保障隔离性能。
- **合规（GDPR / 个保法）**：学者可申请**查看 / 删除**其非法定保留个人数据；删除权受 §9 法定保留（离职档案 15 年、涉密/涉腐审计期）约束——冲突时执行**软删 + 加密封存**（`deleted=1` + 敏感列密钥销毁/隔离），保留可查询最小集供法定用途，删除请求与依据全程审计留痕。

## 8. 异常与边界

| 场景 | 处理 |
|------|------|
| **同名同姓学者** | 工号 + ORCID 双主键区分（§4.3）；仅姓名命中不并档。 |
| **跨机构外部学者** | **不入本院 S_STAFF 主表**，走 EXPERT（外部专家库，M2/06 定义）；合作网络以虚节点或 EXPERT 关联呈现；如需短期入驻本院则转 S_VISITOR（建临时 sys_user + S_STAFF，到期失效）。 |
| **人事变更未同步（S-01）** | svc-integration-hr **定时对账**（每日比对 HR 差异）+ **手动纠错入口**（管理员发起校正，写审计）；对账发现 employment_status 漂移→告警 + 建议动作。 |
| **PI 突然离职** | 未交接前其名下项目经费**冻结**（§4.1），阻断新报销/外拨；强制 handover 校验。 |
| **退休返聘** | employment_status 支持 `REHIRE`；权限按新身份重评（sys_user_role 重授），保留退休前历史画像与成果归属。 |
| **双聘** | 一人多部门，主部门唯一，次部门 effort 分摊（§4.4）；绩效/成本跨部门可分配。 |
| **跳槽换机构** | 历史成果保留原单位（R affiliations 冻结快照，S_USR-05）；个人 ORCID 账号可跨机构关联，院内档案转 RESIGNED/INACTIVE 保留可查。 |
| **画像事件风暴** | 同学者短时间多事件→去抖合并（按 staff_id+窗口聚合后再刷快照），避免快照表抖动。 |
| **外部标识冲突** | ORCID 被两人声明→人工复核队列，暂以工号为准并标记待核。 |

## 9. 非功能

- **人员列表性能**：5000 人 **< 500ms**（主路径组合索引 + GIN 方向标签 + 分页；达梦全文退 ES）。
- **画像批量刷新**：全院 5000 人 **< 30 min**（svc-profile 分片批处理，幂等 upsert `uk_portrait_day`）。
- **合作网络渲染**：**< 2000 节点** 力导向图流畅渲染；ego 子图 + min_weight 边过滤 + snapshot 切片控制规模。
- **数据保留**：离职人员档案保留 **15 年**（可查询不可编辑，status=INACTIVE + deleted 保留），到期后按留存策略归档冷存。
- **可靠性**：客座权限到期自动失效 **100%**（调度双保障：expires_at 校验 + 事件 revoke）。
- **覆盖**：科研人员档案 100% 覆盖（HR 同步 + 手动补建）；PI 画像自动化覆盖全院 PI 100%。
- **对接**：主流 HR 系统对接 ≥ 2 家（北森/SAP/用友）+ CAS/LDAP + ORCID + 微信企业号。
- **合规与安全**：敏感字段加密落库；字段级访问审计（sys_audit_log）；GDPR/个保法删除权与法定保留平衡（§7）。
- **可复算**：画像数值口径与梯队规则命中记 `sys_rule_hit` + `policy_pack_id` 快照，支持审计复算。
