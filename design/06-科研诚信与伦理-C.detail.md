## 1. 范围与依赖

本模块把合规与伦理审查从"事后补票"改造为**嵌入业务前置卡点**：伦理未批则涉人样本项目无法提交申报；批件到期则联动冻结经费支付。核心链路为 **"伦理申请 → AI 预审 → 形式审查 → 分派主审+委员 → 独立审阅 → 会议/简化审查 → 决议批件 → 年度复审与跟踪"**，并行覆盖**诚信承诺、失信档案与申诉、学术不端检测、人类遗传资源备案**。

功能范围（C-01..C-19）：

| 编号 | 功能 | 优先级 | 本文落点 |
|------|------|--------|----------|
| C-01 | 伦理审查类型配置（人体/动物/生安/人遗/数据出境） | P0 | §3 `C_ETHICS_CASE.review_type`、字典 |

**依赖（跨模块，只存对方主键 `id` 作逻辑外键，一致性走 Kafka 事件，见 §5）**：
- **01 项目申报与立项（P）**：`ethics.approved` 是涉人/涉动物样本申报提交的**前置卡点**（消费方 P）。诚信承诺（申报类）为提交前置之一。
- **02 项目过程管理（E）**：`E_PROJECT`（`project_id` 逻辑引用）；E 侧已定义 `ethics_case_id`（02 detail §3），与本模块互为逻辑外键。
- **03 科研经费管理（F）**：`ethics.expiring`/`EXPIRED` 联动触发**经费支付自动冻结**（消费方 F，见 §4.3）。
- **04 科研成果管理（R）/ 05 转化（T）**：`C_MISCONDUCT_SCAN` 对 `PAPER/DEAL/OUTPUT` 多态目标做查重（`target_id` 逻辑引用 R_OUTPUT.id / DEAL.id）。
- **X 涉密管理**：涉密正文、数据出境材料、涉外/人遗涉密件移交 X；本模块只留 `security_level` 与 `x_ref`（EXF 号）引用，不存正文。
- **svc-integration**：查重 CNKI/Turnitin、国家人遗管理服务系统、电子签名服务。
- **横切底座（00-common）**：`sys_dict`（承诺类型/事件类型/审查类型/备案类型）、`sys_policy_pack`/`sys_rule_hit`（回避规则/前置卡点阈值/复审周期可配）、`seq_prefix_registry`（前缀 ETH，已登记）、`sys_audit_log`（复用通用审计）、`x_flow_audit`（涉密外传留痕）。

## 2. 服务与分层

微服务划分（一模块一库，跨库只存对方 `id`，一致性走 Kafka 事件）：

```
svc-compliance（C 主服务）
├─ interfaces  : REST（06-...openapi.yaml）/ DTO / Assembler
│                ├─ 伦理案卷读接口施加受试者信息权限隔离过滤器（SubjectGuard）
│                └─ 批件公开验证接口 verify 走免鉴权白名单 + 限流
├─ application : 案卷状态机驱动、分派编排、会议表决汇聚、承诺签署、失信/申诉编排、幂等
├─ domain      : C_ETHICS_CASE 聚合根 + 各从表实体 + 规则策略（回避矩阵/前置卡点/复审周期/出境关键词）
└─ infra       : PG(15) 仓储、Kafka 生产/消费、对象存储附件、状态到期/超期调度扫描

svc-workflow（审查流转编排，被 svc-compliance 调用）
├─ assign      : 主审(CHIEF)+委员(BOARD)分派、回避校验、审阅时限与超期升级催办
├─ review      : 独立审阅收集、意见/打分汇聚、会议→决议流转
└─ appeal      : 失信档案申诉独立子流程（FILED→REVIEWING→UPHELD/OVERTURNED）

svc-integration（外部系统对接，被 svc-compliance 调用）
├─ dup         : CNKI 查重 API / Turnitin API（可选）适配器，异步回写 C_MISCONDUCT_SCAN
├─ hgr         : 国家人类遗传资源管理服务系统备案提交/状态拉取（sync_batch_id 回执追溯）
└─ esign       : 电子签名服务（承诺签署 signature_url、批件签章）

svc-ai-gateway（AI 中台，被 svc-compliance 调用）
├─ prescreen   : LLM 伦理风险预判（检索历史风险事件 + 关键要素完整性），出 risk_points/confidence
└─ misconduct  : 多模态 LLM + pHash/CNN + Benford 数据异常，进阶不端识别（C-18），附置信度
```

分层约束：`interfaces` 不触库；`domain` 不依赖框架；`infra` 实现仓储与适配器；**跨模块联动一律通过事件解耦**（申报解锁→P、支付冻结→F、失信回写画像→S）。前置卡点、回避、权限隔离、到期/超期调度属**规则引擎与调度**，不做语义判断；伦理风险预判、不端识别属 **LLM/多模态**，只出建议 + 置信度，人工兜底。

## 3. 数据模型明细

> 通用列（`id/code/tenant_id/status/deleted/creator_id/modifier_id/created_at/updated_at/remark`）见 `./README.md` §2.1，下表只列业务列。半结构化用 JSONB，比例/置信度用 `NUMERIC(6,4)`，时间 `TIMESTAMPTZ`/纯日期 `DATE`（§2.2）。**以 `C_ETHICS_CASE` 为聚合根**，其余审查表 1:N/1:1 挂其下。

### 3.1 C_ETHICS_CASE（伦理审查案卷，聚合根）

| 列 | 类型 | 说明 |
|----|------|------|
| code | VARCHAR(64) | **ETH-年-序**（前缀 ETH 已登记 `seq_prefix_registry`，owner=C，per_entity 分号段） |
| status | VARCHAR(32) CHECK | 案卷状态机（§4.1）：DRAFT/SUBMITTED/FORMAL_CHECK/UNDER_REVIEW/NEEDS_REVISION/APPROVED/REJECTED/MONITORING/EXPIRED |
| review_type | VARCHAR(32) CHECK | HUMAN/ANIMAL/BIO_SAFETY/HGR/DATA_EXPORT（C-01） |
| project_id | BIGINT | **逻辑引用 E_PROJECT.id**，可空（预申报阶段案卷先于立项） |
| applicant_user_id | BIGINT | PI/申请人，`sys_user.id` 逻辑引用 |
| department_id | BIGINT | 申请所属 `sys_org.id`，**回避判定用**（同部门强制回避） |
| protocol_title / protocol_summary / methodology | VARCHAR/TEXT | 方案标题/摘要/方法学；**摘要涉受试者信息，读接口权限隔离（敏感）** |
| risk_level | VARCHAR(16) CHECK | HIGH/MED/LOW：HIGH 走会议审查，LOW 可紧急/简化（PRD §6.1） |
| materials | JSONB | `[{name,url,type,uploaded_at}]` 方案/招募材料等附件 |
| informed_consent_url | VARCHAR(512) | 知情同意书地址，可追溯（PRD §12） |
| risk_assessment | JSONB | AI 伦理风险预判 `{risk_points[],need_supplement[],confidence}` |
| ai_prescreen | JSONB | 关键要素完整性 `{missing_fields[],passed}` |
| submitted_at | TIMESTAMPTZ | 正式提交（进入 FORMAL_CHECK 前置） |
| decision_date / valid_until | DATE | 决定日期 / 批件有效期截止（到期→EXPIRED 联动 F 冻结） |
| next_review_at | DATE | 下次年度复审日（30 天提前提醒扫描主键） |
| is_emergency | BOOLEAN | 紧急/快速通道（C-05） |
| legal_entity_id / security_level / policy_pack_id / x_ref | — | 治理三字段 + 移交 X 涉密审计引用；**涉密正文由 X 管理** |

| 表 | 基数 | 关键业务列 | 状态 CHECK |
|----|------|-----------|-----------|
| **C_REVIEWER_ASSIGN** | 1:N | case_id/reviewer_user_id/role(CHIEF/BOARD)/assigned_at/deadline/conflict_of_interest/coi_reason | ASSIGNED/ACCEPTED/RECUSED/COMPLETED/TIMEOUT/REASSIGNED |

| **C_MEETING_RECORD** | 1:N | case_id/meeting_date/attendees(JSONB 签到)/quorum_met/discussion_text/decision/vote_result(JSONB) | SCHEDULED/IN_PROGRESS/MINUTED/FINALIZED |
| **C_DECISION_LETTER** | 1:1 | case_id(UNIQUE)/decision_type/letter_no/letter_url/verify_url/qr_code_url/signature_url/issued_at/**expires_at TIMESTAMPTZ** | DRAFT/ISSUED/PUBLISHED/REVOKED/EXPIRED |
| **C_AMENDMENT** | 1:N | case_id/change_summary/materials(JSONB)/submitted_at/decided_at/decision_note | DRAFT/SUBMITTED/UNDER_REVIEW/APPROVED/REJECTED |
| **C_AE_REPORT** | 1:N | case_id/event_date/severity(SERIOUS/NON_SERIOUS/SUSAR)/description(敏感)/action_taken/reported_at/assessed_by | REPORTED/ASSESSING/ACTIONED/CLOSED |

## 4. 关键业务规则

### 4.1 伦理案卷状态机迁移表（含 MONITORING/EXPIRED）

状态 token 见 `./README.md` §4 / PRD §6.2。迁移矩阵（`C_ETHICS_CASE.status`），每次迁移写 `sys_audit_log`（object_type=`C_ETHICS_CASE`）：

| 当前态 \ 动作 | 提交 | 形式审查齐备 | 形式缺件 | 分派完成 | 需修改重报 | 决议批准 | 决议拒绝 | 签批件生效 | 复审通过→跟踪 | 到期/复审逾期 |
|----|----|----|----|----|----|----|----|----|----|----|
| DRAFT | →SUBMITTED | | | | | | | | | |
| SUBMITTED | | →FORMAL_CHECK | | | | | | | | |
| FORMAL_CHECK | | | →NEEDS_REVISION | →UNDER_REVIEW | | | | | | |
| UNDER_REVIEW | | | | | →NEEDS_REVISION | →APPROVED | →REJECTED | | | |
| NEEDS_REVISION | →SUBMITTED（重报） | | | | — | | | | | |
| APPROVED | | | | | | — | | →MONITORING | | →EXPIRED |
| MONITORING | | | | | | | | | →MONITORING（续期） | →EXPIRED |
| REJECTED | 终态（可另案重报） | | | | | | | | | |
| EXPIRED | | | | | | | | | | 终态（复审通过可回 MONITORING） |

- **紧急/简化通道（C-05）**：`is_emergency=TRUE` 且 `risk_level=LOW` 时，跳过会议审查，分派后主审单独或小委员会直接→决议。
- **APPROVED→MONITORING**：批件签发（C_DECISION_LETTER=ISSUED/PUBLISHED）即进入跟踪监测态，等待年度复审与到期扫描。
- **EXPIRED**：由调度扫描 `valid_until`/`C_DECISION_LETTER.expires_at` 到期或年度复审逾期（`C_ANNUAL_REVIEW.status=OVERDUE` 超宽限）触发，并联动 §4.3。
- 非法迁移一律拒绝返回业务错误；`NEEDS_REVISION` 重报回到 SUBMITTED 重新走形式审查。

### 4.2 伦理批件作为申报前置卡点（`ethics.approved` 解锁 01 提交）

**规则引擎裁决（非 LLM）**：01 申报提交时，若申报涉及**人类样本/动物实验**（申报书打标 `requires_ethics=TRUE`），P 服务校验是否存在 `(project_id 或 applicant+protocol)` 关联、`status∈{APPROVED,MONITORING}` 且 `valid_until≥当前日` 的 `C_ETHICS_CASE`，并二次校验对应申报类 `C_INTEGRITY_PLEDGE` 已签署。

```
伦理案卷 APPROVED → 主审签发批件 → svc-compliance 发 ethics.approved（含 projectId/letterNo/validUntil）
                                   → P 服务消费：解锁该申报提交入口（未批不可提交涉人样本）
批件 REVOKED/EXPIRED → 发 ethics.expired → P 服务重新置灰相关申报提交
```

- 卡点条件命中记 `sys_rule_hit`（可解释、可复算），未通过返回业务错误码（见 §8），前端置灰"提交"并引导"发起伦理申请"。
- 批件公开验证与前置卡点相互独立：外部仅可验证编号真伪，P 侧解锁走内部事件，不依赖公开接口。

### 4.3 批件到期经费支付自动冻结（联动 F）

调度每日扫描 `C_DECISION_LETTER.expires_at` 与 `C_ETHICS_CASE.valid_until`：

- 到期前 30 天 → 发 `ethics.expiring`（通知 PI 复审 + 抄送 F/管理）。
- 到期未复审 → 案卷 `status=EXPIRED`、批件 `status=EXPIRED`，发 `ethics.expired`。
- **F 消费 `ethics.expired`**：对 `project_id` 挂起的报销/外拨支付置 `PAY_FROZEN`（仅冻结**新支付放行**，已入账不追溯），与 F 模块本地预算冻结/扣减解耦（03 detail §4.2 为经费内部冻结，本条为伦理联动的外部支付闸门）。
- 复审通过（`C_ANNUAL_REVIEW` APPROVED → 案卷回 MONITORING、批件续期新 expires_at）→ 发 `ethics.approved`（续期语义）→ F 解冻支付。

### 4.4 年度复审 30 天提醒（C-07）

- 分批复件时按制度包（`sys_policy_pack`，默认 12 个月周期）计算 `next_review_at`。
- 调度每日扫描 `next_review_at - 30 天` 生成复审提醒（送达率目标 100%，站内信 + 邮件），引导 PI 提交 `C_ANNUAL_REVIEW`。
- 逾期未提交 → `C_ANNUAL_REVIEW.status=OVERDUE`，超宽限（可配，默认 30 天）升级并触发 §4.3 EXPIRED 判断。

### 4.5 委员利益冲突回避（同部门/师生强制回避，规则引擎）

分派（`POST /ethics/{id}/assign`）时 svc-workflow 对每名候选审查人做回避校验，命中即**拒绝指派**并标记 `conflict_of_interest=TRUE`+`coi_reason`：

| 回避维度 | 判定 | 数据来源 |
|----------|------|----------|
| 同部门 | 审查人 `sys_org.id` = 案卷 `department_id`（或同直属上级） | sys_org / S_STAFF |
| 师生关系 | 审查人与 PI 存在导师/学生边（导学关系图谱） | svc-compliance 关系表 / S 画像 |
| 同项目 | 审查人出现在该案卷 `project_id` 项目成员中 | E_PROJECT 成员（逻辑） |
| 近期合作 | N 年内共同成果/共同申报（可配阈值） | R_OUTPUT / P 申报（逻辑） |

- **会议表决剔除**：回避者不计入 `attendees` 法定人数与 `vote_result`（§3.2 C_MEETING_RECORD）。
- 回避规则参数（窗口年限、部门层级深度）落 `sys_policy_pack.dsl_yaml`，命中记 `sys_rule_hit`。

### 4.6 失信档案与申诉独立流程（C-16）

失信档案**不进伦理案卷状态机**，为两条独立轴：

- **调查轴 `investigation_status`**：`INVESTIGATING`（建档）→ 事实核定 →`SUSTAINED`（成立，出 decision/sanction/影响期）/ `UNSUSTAINED`（不成立）→ `CLOSED`。
- **申诉轴 `appeal_status`**：建档/定论时发 `integrity.record.created` 通知本人，起算 `appeal_deadline`（默认 15 天）；本人 `POST /integrity/records/{id}/appeal` → `FILED` → 纪检复核 `REVIEWING` → `UPHELD`（维持）/`OVERTURNED`（撤销，主 `status=CLOSED`、`is_public=false`）。
- **申诉期内处分生效冻结**：`FILED/REVIEWING` 期间 `sanction` 暂缓执行；`OVERTURNED` 回滚处分并撤销对外公开。
- 可见性：默认仅**纪检 + 本人**可见，`is_public=TRUE` 才对外（部分公开），越权 `403`（§7）。

### 4.7 审查超期自动升级催办（规则 + 调度）

- `C_REVIEWER_ASSIGN.deadline` 为审阅时限；调度每日扫描未完成（`status∈{ASSIGNED,ACCEPTED}`）且 `deadline < now()` → 置 `TIMEOUT`。
- 分级升级：超时 T+1 通知委员本人 → T+3 通知主审/管理员催办 → T+7 自动 `REASSIGNED`（管理员重派），案卷停留 `UNDER_REVIEW` 不误推进。
- 平均审查周期目标 < 15 天（PRD §1），周期数据回流用于 SLA 看板。

### 4.8 数据出境 / 涉密关键词拦截（C-13/C-19，规则引擎 + X 联动）

- `review_type=DATA_EXPORT` 与 `HGR`（国际合作）案卷、以及人遗备案涉外材料，提交时经规则引擎对正文/材料名做**涉密关键词与出境敏感要素扫描**（制度包维护词表）。
- 命中 → `security_level` 升 `SECRET/TOP_SECRET`，**正文不落本模块**：置 `x_ref`（EXF 号）移交 X 走涉密外传审批（`x_flow_audit`），本模块仅存密级标记与引用；未放行前 `status` 不得进入 APPROVED。
- 原则：**本模块不存涉密正文**，只做密级标注 + 移交引用 + 出境拦截卡点。

### 4.9 规则引擎 vs LLM 分工

| 能力 | 实现方 | 说明 |
|------|--------|------|
| 申报前置卡点（§4.2） | **规则引擎** | 关联案卷存在性 + 有效期 + 承诺签署，确定性强，绝不交 LLM 放行 |
| 批件到期支付冻结（§4.3） | **规则 + 调度** | expires_at 日期比较触发事件 |
| 年度复审提醒（§4.4） | **调度** | 日期窗口扫描 |
| 委员利益冲突回避（§4.5） | **规则引擎** | 同部门/师生/同项目图谱判定，参数可配 |
| 审查超期升级（§4.7） | **规则 + 调度** | deadline 比较 + 分级 |
| 失信调查/申诉状态流转（§4.6） | **规则引擎（独立状态机）** | 人工裁决，系统仅管状态与留痕 |
| 数据出境/涉密关键词拦截（§4.8） | **规则引擎（词表）** + X | 确定性拦截，正文移交 X |
| AI 伦理风险预判（C-17） | **LLM（svc-ai-gateway）** | 检索历史风险 + 要素完整性，出 risk_points + confidence，**辅助非裁决** |
| 学术不端识别（C-14/C-18） | **规则 + 多模态 LLM** | 相似度阈值判定走规则，图片篡改/选择性呈现/方法缺失走 pHash/CNN/Benford/多模态 LLM，附置信度 |
| 查重接口对接（CNKI/Turnitin） | **svc-integration** | 外部确定性服务 |

原则：**前置卡点 / 回避 / 权限 / 到期 / 状态流转 = 规则引擎与调度（可复算可审计）；风险预判 / 不端识别 = LLM+多模态（出建议 + 置信度）；最终放行/定论 = 人工兜底（主审/纪检）**。AI 结论一律落 JSONB（`risk_assessment`/`C_MISCONDUCT_SCAN.confidence`）不直接改业务状态；`SUSPECTED` 需人工确认后才升级为失信调查（`investigation_id` 回指）。

## 7. 权限与隔离

在 PRD §9 权限矩阵（R-STAFF / R-ETHICS(委员) / 主审 / R-MANAGER / 纪检 / R-AUDITOR / R-ADMIN）基础上，补充可见性与密级规则：

- **提交伦理申请**：仅 R-STAFF/PI 对自己案卷。**审阅与打分**：仅被分派且非回避的委员（`/ethics/{id}/opinion`）。**签发批件**：仅主审 CHIEF。
- **案卷查看范围**：PI 见自己 `applicant_user_id`；委员见被 `C_REVIEWER_ASSIGN` 分派者；R-MANAGER/纪检/R-AUDITOR 见全部；R-ADMIN 无业务可读（三员分立，见 `sys_admin_duty`）。
- **受试者信息严格隔离（PRD §9 保密）**：`protocol_summary`/`methodology`/`C_AE_REPORT.description`/知情同意材料等涉受试者内容，仅授权角色可读，无权角色查询 `403` 或字段脱敏；委员意见对 PI **匿名**展示。
- **批件编号可查内容不可查**：`GET /ethics/letter/{letterNo}` 免鉴权，仅返回 `valid/decision_type/有效期/状态/二维码`，**绝不返回**申请人、项目、受试者内容（§6）。
- **失信记录可见性**：默认仅**纪检 + 本人**可见（个人档案"诚信"标签页），普通角色 `403`；`is_public=TRUE` 的记录才部分对外（`integrity_flag` 回写 S 画像同样受限，见 07 detail §7）。
- **学术不端扫描结果**：仅触发人（自己成果）、管理员、纪检、审计可见；`SUSPECTED/CONFIRMED` 报告对普通角色不可见。
- **涉密隔离（C-19）**：`security_level∈{SECRET,TOP_SECRET}` 的案卷/备案，正文不落本模块（`x_ref` 移交 X），列表/详情/导出/打印一律密级过滤；跨密级域上下行经 `x_flow_audit`（EXF）留痕，与三员账号联动。
- **数据隔离**：所有查询强制注入 `tenant_id`（总院法人边界）+ `legal_entity_id`（法人细分）；主路径索引 `(tenant_id, legal_entity_id, status)` 保障隔离下检索性能。

## 9. 非功能

- **性能**：单案卷 PDF 加载 < 2s（对象存储 + 预签名 URL + CDN）；查重扫描 1 万字符 < 60s（异步任务 + CNKI/Turnitin 并发 + 分片，`C_MISCONDUCT_SCAN.status=RUNNING` 轮询/回调）。伦理审查平均周期 < 15 天（超期催办保障，§4.7）。
- **合规**：满足《赫尔辛基宣言》、《涉及人的生命科学和医学研究伦理审查办法》（2023）等；知情同意书可追溯（`informed_consent_url` + 版本）；**案卷保留 ≥ 10 年**——逻辑删除不物理删、审计哈希链（`sys_audit_log.sig/prev_sig`）不可篡改。
- **可解释 / 可复算**：前置卡点、回避、出境拦截命中 `sys_rule_hit`，案卷落 `policy_pack_id` 快照，支持复算与追溯。
- **AI 可靠性**：所有 AI 输出带 `confidence`（`NUMERIC(6,4)`）与出处，仅作建议；裁决权在主审/纪检（人工兜底），不直接改业务状态。
- **可用性 / 降级**：外部查重/国家人遗/电子签名不可用时降级（手动录入/异步补推/离线签署存证补传），不阻塞核心审查流转。
- **安全**：涉密正文零存储（仅 `x_ref`）；受试者信息读接口隔离；公开验证只暴露编号元数据；三员分立 + 全量字段级审计。
