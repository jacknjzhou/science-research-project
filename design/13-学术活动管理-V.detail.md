> 契约见 design/13-学术活动管理-V.openapi.yaml；建表见 design/13-学术活动管理-V.ddl.sql；术语/编号以 PRD/README 为准。

## 1. 数据字典

模块 V（学术活动）由 3 张业务表构成：**v_activity**（活动主表，申报→审批→举办→归档）、**v_activity_participant**（参与人）、**v_activity_review**（多级审核留痕）。方言 PostgreSQL 15；金额 `NUMERIC(18,2)`、时间 `TIMESTAMPTZ`、枚举一律 `VARCHAR + CHECK`、字典项走 `sys_dict`。

**跨模块引用均为逻辑外键（不建物理 FK）**：`organizer_dept_id → sys_org`、`project_id → e_project`、`budget_subject_code → F 科目 / sys_dict`、`user_id / reviewer_id → sys_user`。**同模块内 participant / review 对 v_activity 建物理外键**（`activity_id REFERENCES v_activity(id)`）。编号 `v_activity.code` 前缀 `ACT`（由 svc-numbering 分配，见 00-common `seq_prefix_registry`）。

### 1.1 v_activity（活动主表）

主键 `id BIGINT IDENTITY`；`code`（业务单号，ACT-年-序）；多租户列 `tenant_id`；通用审计列 `status / deleted / creator_id / modifier_id / created_at / updated_at / remark`。

| 列 | 类型 | 说明 |
|----|------|------|
| `status` | VARCHAR(32) NOT NULL DEFAULT 'DRAFT' | 状态机 token（见 §1.5、§2），CHECK 约束 |
| `security_level` | VARCHAR(16) NOT NULL DEFAULT 'INTERNAL' | 密级；读取按网络域/密级过滤（复用 X 治理谓词），CHECK 约束 |
| `activity_type` | VARCHAR(32) NOT NULL | 活动类型，CHECK 约束 |
| `level` | VARCHAR(16) | 活动级别，CHECK 约束 |
| `host_mode` | VARCHAR(16) | 主办方式，CHECK 约束 |
| `title` | VARCHAR(256) NOT NULL | 活动名称 |
| `theme` | VARCHAR(256) | 主题 |
| `start_at` / `end_at` | TIMESTAMPTZ | 起止时间 |
| `venue` | VARCHAR(256) | 线下地点 |
| `online_url` | VARCHAR(512) | 线上链接 |
| `host_unit` | VARCHAR(128) | 主办单位（文本快照） |
| `organizer_dept_id` | BIGINT | 主办部门，逻辑外键 → `sys_org(id)`，不建物理 FK |
| `invited_experts` | JSONB NOT NULL DEFAULT '[]' | 邀请专家 `[{name,org,title}]` |
| `est_attendees` | INT | 预计参会人数 |
| `project_id` | BIGINT | 关联项目，逻辑外键 → `e_project(id)` |
| `budget_subject_code` | VARCHAR(64) | 预算科目，逻辑引用 F 科目 / `sys_dict` |
| `budget_amount` | NUMERIC(18,2) | 活动预算（登记），不联动经费冻结（YAGNI） |
| `agenda` | JSONB NOT NULL DEFAULT '[]' | 多场次议程 `[{title,speaker,startAt,endAt,venue}]` |
| `attachment_ids` | JSONB NOT NULL DEFAULT '[]' | 申报材料附件对象 id |
| `minutes_rich` | TEXT | 纪要（归档时填写） |
| `sign_in_count` | INT | 实到人数 |
| `hold_proof_ids` | JSONB NOT NULL DEFAULT '[]' | 举办凭证对象 id |
| `submit_at` / `approve_at` / `archive_at` / `cancel_at` | TIMESTAMPTZ | 各关键动作时间戳 |
| `cancel_reason` | VARCHAR(512) | 取消原因 |

索引/唯一：
- 唯一 `uk_v_activity_code (tenant_id, code) WHERE deleted = 0`（软删后单号可复用，活跃记录内单号唯一）。
- `idx_v_activity_tenant_st (tenant_id, status)`、`idx_v_activity_type (tenant_id, activity_type)`、`idx_v_activity_level (tenant_id, level)`、`idx_v_activity_dept (organizer_dept_id)`、`idx_v_activity_project (project_id)`、`idx_v_activity_start (start_at)`。

### 1.2 v_activity_participant（参与人）

| 列 | 类型 | 说明 |
|----|------|------|
| `id` | BIGINT IDENTITY PK | 主键 |
| `activity_id` | BIGINT NOT NULL | **物理外键** → `v_activity(id)` |
| `user_id` | BIGINT | 逻辑外键 → `sys_user(id)`；为空表示外部人员 |
| `guest_name` | VARCHAR(64) | 外部人员姓名快照 |
| `role` | VARCHAR(16) NOT NULL | 参与角色，CHECK 约束 |
| `report_title` | VARCHAR(256) | 报告/发言题目 |
| `tenant_id` | BIGINT NOT NULL | 多租户 |
| `created_at` | TIMESTAMPTZ NOT NULL DEFAULT now() | 创建时间 |

唯一 `uk_v_participant_user (activity_id, user_id, role) WHERE user_id IS NOT NULL`（同一内部用户在同一活动同一角色不重复；外部 guest 不受此约束）。索引 `idx_v_participant_activity (activity_id)`。

### 1.3 v_activity_review（多级审核留痕）

| 列 | 类型 | 说明 |
|----|------|------|
| `id` | BIGINT IDENTITY PK | 主键 |
| `activity_id` | BIGINT NOT NULL | **物理外键** → `v_activity(id)` |
| `review_level` | SMALLINT NOT NULL | 审核级别（1=部门，2=院所/主管） |
| `reviewer_id` | BIGINT NOT NULL | 审核人，逻辑外键 → `sys_user(id)` |
| `action` | VARCHAR(16) NOT NULL | 审核动作，CHECK 约束 |
| `opinion` | VARCHAR(512) | 审核意见 |
| `acted_at` | TIMESTAMPTZ NOT NULL DEFAULT now() | 动作时间 |
| `tenant_id` | BIGINT NOT NULL | 多租户 |

索引 `idx_v_review_activity (activity_id, review_level)`。每级审批动作/意见/时间可追溯。

### 1.4 CHECK 约束枚举一览

| 字段 | 枚举 token |
|------|-----------|
| `activity_type` | `CONFERENCE` / `LECTURE` / `SEMINAR` / `TRAINING` / `OTHER` |
| `level` | `INTERNATIONAL` / `NATIONAL` / `PROVINCIAL` / `CAMPUS` |
| `host_mode` | `HOST` / `ATTEND` / `SPONSOR` |
| `security_level` | `PUBLIC` / `INTERNAL` / `SECRET` / `TOP_SECRET`（默认 INTERNAL） |
| participant `role` | `SPEAKER` / `CHAIR` / `MEMBER` / `ATTENDEE` |
| review `action` | `APPROVE` / `REJECT` / `RETURN` |

### 1.5 v_activity.status 状态 token（全枚举）

共 9 个 token，与 DDL CHECK 一致：

`DRAFT`（草稿）、`SUBMITTED`（已提交）、`DEPT_REVIEW`（部门审核中）、`APPROVED`（已批准）、`HELD`（已举办）、`ARCHIVED`（已归档，终态）、`REJECTED`（已驳回，终态）、`RETURNED`（已退回，可编辑重提）、`CANCELLED`（已取消，终态）。

## 2. 状态机（端点驱动、硬编码，非通用引擎）

状态迁移由具体端点触发，不引入通用工作流引擎。下图为 `v_activity.status` 的合法迁移（源自规格 §3.2）：

```
DRAFT ──submit──▶ SUBMITTED ──approve(L1)──▶ DEPT_REVIEW ──approve(L2)──▶ APPROVED
  ▲                    │ REJECT/RETURN ───────────────────────────────▶ RETURNED ──(edit)──▶ DRAFT
  └──────(edit/RETURN)─┘
APPROVED ──hold──▶ HELD ──archive──▶ ARCHIVED
任意非终态 ──cancel──▶ CANCELLED
```

端点 → 迁移映射（tag: activity）：

| 端点 | 迁移 |
|------|------|
| `POST /activities/{id}/submit` | `DRAFT` / `RETURNED` → `SUBMITTED` |
| `POST /activities/{id}/approve` | `SUBMITTED` →(L1 APPROVE) `DEPT_REVIEW` →(L2 APPROVE) `APPROVED`；`REJECT`→`REJECTED`；`RETURN`→`RETURNED` |
| `POST /activities/{id}/hold` | `APPROVED` → `HELD` |
| `POST /activities/{id}/archive` | `HELD` → `ARCHIVED` |
| `POST /activities/{id}/cancel` | 任意非终态 → `CANCELLED` |

规则（硬编码校验）：

- 合法迁移由对应 handler 依据当前 `status` 校验，不在合法迁移集合内的一律拒绝。
- 非法迁移返回业务码 `40901`。
- `REJECT` → 终态 `REJECTED`；`RETURN` → `RETURNED`，`RETURNED` 可编辑并可再次提交（回 `DRAFT`/`SUBMITTED`）。
- 归档（`HELD` → `ARCHIVED`）要求当前状态已是 `HELD` **且**纪要 `minutes_rich` 非空。
- 可编辑性：`PUT /activities/{id}` 仅在 `DRAFT` / `RETURNED` 允许，其余状态编辑返回非法。

## 3. 权限矩阵

行=能力，列=角色；`✓` 允许、`只读` 仅查看、`—` 不允许。策略依据规格 §3.4（`R-ADMIN` 由 `/api/v1/*` 通配整体兜底）。

| 能力 | R-STAFF | R-MANAGER | R-LEADER | R-AUDITOR | R-ADMIN |
|------|:-------:|:---------:|:--------:|:---------:|:-------:|
| 新建（POST /activities） | ✓ | ✓ | ✓ | — | ✓ |
| 编辑（PUT，仅 DRAFT/RETURNED） | ✓（限本人发起） | ✓ | ✓ | — | ✓ |
| 提交（submit） | ✓（限本人发起） | ✓ | ✓ | — | ✓ |
| 审批（approve，按 review_level） | — | ✓ | ✓ | — | ✓（兜底） |
| 举办（hold） | — | ✓ | ✓ | — | ✓ |
| 归档（archive） | — | ✓ | ✓ | — | ✓ |
| 取消（cancel） | — | ✓ | ✓ | — | ✓ |
| 查看（列表/详情/日历/统计） | 只读 | ✓ | ✓ | 只读 | ✓ |
| 参与人维护（participants GET/POST/DELETE） | ✓（限本人发起） | ✓ | ✓ | — | ✓ |

要点：

- **建/提交/编辑本人发起**：`R-STAFF`、`R-MANAGER`、`R-LEADER`（编辑/提交限本人发起，由 handler ABAC 再收敛）。
- **审批 approve**：`R-MANAGER`、`R-LEADER`（对应 `review_level`）；`R-ADMIN` 兜底。
- **R-AUDITOR 只读**：仅 `GET`，不可发起/审批/维护参与人。
- **查看过滤**：列表/详情按 `tenant_id + security_level` 过滤——涉密活动仅对应网络域/密级可见，复用模块 X 的读取谓词 hook。

分层说明：**Casbin RBAC 是传输层**，`policy.csv` 以 `keyMatch2` 通配 `/api/v1/activities*` 做粗粒度放行（`R-STAFF` 覆盖 `/activities POST`、`/activities/* GET|PUT`、`/activities/*/submit POST`、`/activities/*/participants*`；`R-MANAGER`/`R-LEADER` 追加 `/activities/*/approve|/hold|/archive|/cancel`；`R-AUDITOR` 仅 `GET`；`R-ADMIN` 走 `/api/v1/*` 通配）。**逐行 ABAC 在 handler 内强制**——多租户 `tenant_id`、密级 `security_level` 读取过滤、以及编辑/提交/参与人维护时的“归属本人发起”校验；`BuildCaps` 将上述 p 规则派生为前端 `caps` 并由 `/auth/me` 回显。
