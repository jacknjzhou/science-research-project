## 1. 范围与依赖

**依赖**：
- **04 成果管理（R）**：`R_OUTPUT`（披露与交易标的来源，逻辑外键 `output_id`）。
- **03 经费管理（F）**：到账 `received` 入账关联（逻辑外键 `finance_receipt_id`），分配发放金额回流经费台账。

- **国家技术转移交易平台**：挂牌推送（PRD §10）。
- **横切底座（00-common）**：`sys_dict`、`sys_policy_pack`/`sys_rule_hit`（审批门槛/分配规则）、`seq_prefix_registry`（`DEAL` 前缀）、`sys_audit_log`（哈希链审计）、`sys_print_template`（合同/年报套打）。

## 2. 服务与分层

一模块一库，跨库只存对方 `id`，一致性走 Kafka 事件（`./README.md` §3.1、`../TECH_ARCHITECTURE.md` §八）。

```
svc-transfer（T 主服务）
├─ interfaces  : REST（05-...openapi.yaml）/ DTO / Assembler
├─ application : 交易状态机驱动、披露/评估编排、公示倒计时调度、幂等、批量
├─ domain      : T_DEAL 聚合根 + Disclosure/Valuation/Contract/Approval/Income/Distribution/Publicity 实体
│                + 状态机、异议独立状态机、作价入股退出、争议仲裁暂缓策略
└─ infra       : PG(15) 仓储、Kafka 生产/消费、对象存储（合同/报告/凭证，合同永久保留）

svc-policy（确定性判定服务，规则引擎，非 LLM）
├─ approval-gate : T-08 审批权限门槛（金额阈值→需院所/理事会），出 approval_required_level，落 policy_pack_id
├─ dist-engine   : T-12 收益分配（团队/院所/个人比例、min_team_pct 拦截、分期/提成按期计算）
└─ hit-audit     : 命中记 sys_rule_hit（可解释、可复算）

svc-workflow（多级审批引擎）
└─ 顺序/并行审批链实例化到 T_APPROVAL_CHAIN；驳回回退；到期提醒；全量留痕

svc-integration-seal（电子签章适配）
└─ e签宝/法大大/CFCA：发起签、回调写 seal_records + signed_at → deal.signed

svc-integration-biz（工商核验适配）
└─ 天眼查/企查查：签约前核验，异常回写 check_abnormal → 前端标红阻断

svc-integration-eval（评估机构适配）
└─ 报告上传/邮件对接 → T_VALUATION(valuator_type=EXTERNAL)

svc-integration-nat（国家技术转移平台）
└─ 挂牌信息推送（T-05）

svc-ai-gateway（LLM，被 svc-transfer 调用，附置信度）
├─ opportunity : T-17 专利族向量化 + 企业技术需求相似度 + GNN 合作网络
├─ clause-risk : T-18 逐条对照法条，输出 {clause,severity,issue,suggestion,ref_article}
└─ pricing     : T-19 可比交易 + 行业指标 → 定价区间（仅供参考，不硬约束）

svc-numbering（统一编号中心）
└─ 下发 T_DEAL.code = DEAL-年-序（per_entity 分号段）
```

分层约束：`interfaces` 不触库；`domain` 不依赖框架；`infra` 实现仓储与适配器；**审批门槛、分配比例判定一律经 svc-policy 规则引擎，绝不由 LLM 直接裁决**（对齐 PRD 2.4/2.10、本文 §4.9）。

## 3. 数据模型明细

> 通用列（`id/code/tenant_id/status/deleted/creator_id/modifier_id/created_at/updated_at/remark`）见 `./README.md` §2.1，各表内联、列名列型完全一致，下表只列业务列。半结构化用 JSONB；金额 `NUMERIC(18,2)`、比例 `NUMERIC(6,4)`；时间 `TIMESTAMPTZ`/`DATE`。**PK=主键、FK=同模块物理外键、LOGICAL=跨模块逻辑外键**。

### 4.2 T-02 转化方式与支付方式

- `deal_type` 六种：转让/独占许可/排他许可/普通许可/作价投资/合作实施，映射到分配规则 `applies_to`（转让/许可/作价）。
- `payment_method` 三种驱动到账与分配模式（§4.6/§4.7）：一次性、分期（`term_start/term_end` 分期，每期触发分配）、入门费+销售提成（`initial_fee` + `royalty_rate`，提成按企业上报销售额计提）。

### 4.3 评估分派（T-03 内评 / T-04 外评）

- 披露进入 `UNDER_EVAL`，转化办发起 `POST /disclosure/{id}/valuation` 创建 `T_VALUATION`。
- `valuator_type=INTERNAL`：分派内部评估小组（`valuator_name`），小组在线填报 `method + valuation_amount`。
- `valuator_type=EXTERNAL`：登记机构（`valuator_org`），机构通过 `POST /valuation/{id}/external-report` 上传报告（`report_url`）与 `valuation_amount/valid_until`。
- 评估结论 `CONFIRMED` 后作为 `T_DEAL.contract_amount` 定价基准之一；`T-19 AI 定价` 结果写 `ai_pricing_ref`，**仅供参考**（§4.9）。

### 4.4 T-08 审批权限门槛（金额阈值 → 需院所/理事会，规则引擎 + policy_pack_id）

**确定性判定，走 svc-policy 规则引擎，绝不由 LLM 决定**（PRD 2.4/2.10）。

判定流程（`/deal/{id}/approve` 前，由 `DRAFT_CONTRACT→UNDER_APPROVAL` 时实例化审批链）：

1. 取 `contract_amount`（作价投资取 `equity_value`）+ `legal_entity_id`。
2. 命中当前 ACTIVE 的 `sys_policy_pack`（applied_modules 含 T），执行 `dsl_yaml` 中审批权限矩阵：
   - 例：`amount < 100万` → 审批层级 `[LEGAL, FINANCE, INSTITUTE]`；
   - `100万 ≤ amount < 500万` → 追加 `COMPETENT_DEPT`（主管部门）；
   - `amount ≥ 500万` → 追加 `BOARD`（理事会，对齐 PRD T-USR-08 "500 万以上需理事会审批"）。
3. 输出 `approval_required_level`（最高层级）并逐层实例化 `T_APPROVAL_CHAIN`（每层携 `amount_threshold` 快照 + `policy_pack_id`）。
4. 每次判定写 `sys_rule_hit`（rule_code/verdict/detail_json），`T_DEAL.policy_pack_id` 落快照，支持审计复算。
5. **门槛未满足不得 `→APPROVED`**（业务码 50005）；缺层审批人、层级被跳过 → 拦截。

审批模式：`parallel_group` 相同者可并行，否则按 `step_order` 顺序；任一 `REJECT` 回退 `DRAFT_CONTRACT`；每级看到该合同 `ai_risk_report`（仅提示，不作裁决）。

### 4.5 T-10 电子签与归档

- `APPROVED`（或 `PUBLICIZED` 期满，见 §4.1）后调 svc-integration-seal 发起签署，回调写 `T_CONTRACT.seal_records`（各方签名哈希 + 时间戳）与 `signed_at`。
- 合同正文 `contract_file_url` **永久保留**（PRD §12），红线版 `redline_file_url` 留存；`immutable_hash + prev_hash` 构成版本哈希链。
- 至少对接 1 家供应商（e签宝/法大大/CFCA），供应商不可用时降级线下签 + 上传扫描件补录 `seal_records`。

### 4.6 T-11 到账登记与匹配

- `EXECUTING` 期，R-FINANCE 通过 `POST /income` 登记到账（`bank_flow_no` 部分唯一防重复，业务码 50008）。
- 与 03 经费到账/认领 `finance_receipt_id` 逻辑关联，`/income/{id}/match` 按银行流水号匹配。
- 提成模式：企业定期上报销售额 → `sales_amount`；`royalty_calc_amount = sales_amount × T_DEAL.royalty_rate` 计提后再分配（PRD §11）。
- 到账登记成功即发 `income.received`，驱动 §4.7 分配计算。

### 4.7 T-12 收益分配规则引擎（确定性计算，非 LLM）

- **规则选择**：`/income/{id}/distribution` 按 `T_DEAL.deal_type → applies_to` + 到账日落在 `effective_from/effective_to` 区间，命中唯一 ACTIVE 规则；缺省自动命中，可传 `rule_id` 覆盖。
- **三拆**：`team_amount=total×team_pct`、`institute_amount=total×institute_pct`、`individual_amount=total×individual_pct`（`total_amount` 为到账净额）。
- **min_team_pct 拦截**：若命中规则 `team_pct < min_team_pct` 或手工覆盖比例低于最低限 → **拒绝保存**（业务码 50003），前端可视化滑块同步拦截（PRD 7.5）。
- **分期分配**：`payment_method=分期` 时，每期到账均触发一次 `T_DISTRIBUTION_RECORD`（与 `T_INCOME` 1:1），金额按合同期（`term_start/term_end`）比例切分，逐期累计到合同总额。
- **销售提成模式**：`入门费` 一次性分配；各提成期按 `royalty_calc_amount`（=销售额×royalty_rate）计算后分配。
- **明细到人**：`breakdown=[{user_id,pct,amount,basis}]` 依据 `authors`/发明人份额（来自 04）与贡献；发放前需员工确认（`CONFIRMED`）。
- **可复算**：命中规则号 + `policy_pack_id` 落 `sys_rule_hit`，历史规则留档（`SUPERSEDED`）。
- **作价入股**：`applies_to=作价` 时，现金分红按规则分配，另按 `equity_ratio` 管理股权/退出/收益（§4.11）。

### 4.8 公示期倒计时 + 异议独立状态机（T-14 / PRD §11）

**公示倒计时**：`deal.signed` → 创建 `T_PUBLICITY`（`PUBLISHED`），`publish_end_at = now + duration_days`；调度每日扫描 `idx_publicity_countdown`，到期且 `objection_open=FALSE` → `COMPLETED` 并放行交易进入 `EXECUTING`。

**异议独立状态机**（与交易状态机解耦，落 `T_PUBLICITY.status` + `objections[].handle_status`）：

```
PUBLISHED →（收到异议）OBJECTION_PENDING
  OBJECTION_PENDING →（受理核实）IN_PROGRESS
  IN_PROGRESS →（异议成立）OBJECTION_RESOLVED[SUSTAINED]  → 交易 TERMINATED（OBJECTION_SUSTAINED）
  IN_PROGRESS →（异议不成立）OBJECTION_RESOLVED[DISMISSED] → 恢复倒计时 → COMPLETED → 放行 EXECUTING
```

- **硬约束**：`objection_open=TRUE` 期间，交易**禁止** `→EXECUTING`（业务码 50002）；到账登记不受影响但分配暂缓。
- 异议提交通道公开（`/publicity/{dealId}/objection`，可匿名留联系方式），处置需法务/转化办（`/objection/handle`）。
- 公示记录与 `public_snapshot_hash` 保留 **10 年**（PRD §12）。

### 4.9 规则引擎 vs LLM 分工（对齐 PRD 2.4/2.10）

| 能力 | 实现方 | 说明 |
|------|--------|------|
| T-08 审批权限门槛 | **规则引擎（svc-policy）** | 金额阈值→层级矩阵，确定性、可复算、可审计，落 policy_pack_id |
| T-12 收益分配比例 | **规则引擎（svc-policy）** | 三方比例、min_team_pct 拦截、分期/提成计算，确定性 |
| T-10 电子签 / 哈希链 | **确定性服务 + 加密** | 签名与哈希计算，不涉模型 |
| T-17 转化机会识别 | **LLM/向量（svc-ai-gateway）** | 相似度 + GNN，输出附 `confidence`；不自动定成交 |
| T-18 合同条款风险 | **LLM** | 逐条对照法条，输出 `{clause,severity,issue,suggestion,ref_article,confidence}`；仅供审批人参考，召回率≥85% |
| T-19 定价参考 | **LLM + 可比交易** | 输出区间+依据+案例，**仅供参考，不硬约束**，最终定价以评估机构报告与谈判为准（PRD §8.3） |

原则：**价值裁决（审批门槛、分配比例、是否拦截）一律规则引擎 + 人工；模糊判断（机会、风险、定价）交 LLM 且必附置信度、不越过确定性护栏**。

### 4.10 交易对手真实性校验（PRD §11）

- 发起交易/签约前，svc-integration-biz 调天眼查/企查查按 `partner_credit_code` 核验；返回写 `T_ENTERPARTNER.business_check_json`。
- 命中注销/吊销/失信/严重违法/股权异常 → `check_abnormal=TRUE`（前端标红），交易 `partner_check_abnormal=TRUE`，**阻断 `→APPROVED/→SIGNED`**（业务码 50004）。
- API 超时/不可用 → 标"未核验"，允许转化办人工补录佐证后置核验通过；不允许静默放行。

### 4.11 作价入股额外股权/退出管理（PRD §11）

- `deal_type=作价投资` 必填 `equity_ratio/equity_value/exit_arrangement`。
- 独立子状态跟踪：持股登记 → 年度收益（分红走 §4.7 分配）→ 退出触发（回购/转让/IPO）→ 退出收益分配。
- 退出记录挂 `T_DEAL`，与工商变更/资产评估联动；退出收益作为一笔 `T_INCOME`（`payment_phase=退出`）进入分配链路。

### 4.12 分配争议仲裁可暂缓发放（PRD §11）

- 发明人对 `breakdown` 有异议 → `T_DISTRIBUTION_RECORD.status=DISPUTED`，`dispute_note` 记录。
- 仲裁流程裁决前，`issue` 动作传 `action=HOLD` → `HELD`（`held_reason=ARBITRATION`），**暂缓发放**，不阻断其他无争议明细。
- 裁决后 `action=RESUME` 按裁决调整 `breakdown` 再 `ISSUE`；裁决调整同样写审计与 `policy_pack_id` 复算依据。

| 50012 | 403 | 越权（谈判细节/分配非本人相关/非对应审批层级） |

## 7. 权限与隔离（PRD §9）

- **披露**：R-STAFF CRUD（本人发明人），R-MANAGER/R-AUDITOR 只读。
- **评估/挂牌/谈判**：R-MANAGER CRUD，R-LEADER/R-AUDITOR 只读。
- **合同起草**：R-MANAGER + 法务；**法务角色**独立（审签环节看历史相似合同 + AI 风险提示）。
- **审批**：按 §4.4 层级，仅对应 `approver_role` 用户可办该步；越层/跳步拦截（50012）。
- **电子签**：R-MANAGER 提交、R-LEADER 签署。
- **到账/分配**：R-FINANCE CRUD、R-MANAGER 审、R-LEADER 分配规则审批、R-AUDITOR 只读。
- **公示**：R-MANAGER CRUD；`GET /publicity/{dealId}` **不鉴权**（`security: []`）对外公开，仅返回脱敏 `summary_json`。

**数据可见性**（PRD §9 数据可见性 + §11）：
- **谈判细节仅参与人可见**：`T_DEAL` NEGOTIATING 阶段条款/`partner` 信息经参与人白名单（deal 参与方 + 指定角色）过滤，非参与人查询 `403`。
- **公示后相关摘要对外**：`PUBLICIZED/SIGNED` 后仅 `summary_json`（交易主体/成果摘要/评估价/成交价/分配情况）公开；明细文件不对未登录用户暴露。
- **员工只见与自己相关分配**：`/distribution/mine` 按 `breakdown[].user_id = 当前用户` 过滤，聚合查询走 GIN；他人条目一律不可见。
- **隔离**：所有查询强制注入 `tenant_id`（总院法人边界）+ `legal_entity_id`（法人细分）；`is_core_tech`/涉密（`security_level=SECRET/TOP_SECRET`）走单独权限通道，跨密级域上下行经 `x_flow_audit`（前缀 EXF）留痕。列表/详情/导出/打印一律密级过滤。

## 8. 异常与边界（PRD §11）

| 场景 | 处理 |
|------|------|
| **交易对手风险** | 签约前工商 API 校验，异常 `check_abnormal=TRUE` 标红并阻断 APPROVED/SIGNED（50004）；API 不可用降级人工补录，不静默放行（§4.10）。 |
| **公示异议** | 独立异议状态机（§4.8）；`objection_open=TRUE` 禁止进 EXECUTING（50002）；异议成立 → 交易 `TERMINATED(OBJECTION_SUSTAINED)`。 |
| **分期到账** | 每期 `T_INCOME` 均触发 `income.received` → 按合同期比例生成 `T_DISTRIBUTION_RECORD`（§4.7）。 |
| **销售提成模式** | 企业定期上报销售额 → `sales_amount` → `royalty_calc_amount=sales_amount×royalty_rate` → 分配（§4.6）。 |
| **作价入股** | 额外管理股权/退出/收益（§4.11）；退出收益作为 `payment_phase=退出` 到账进入分配。 |
| **合同变更** | `version+1` 且重大变更走重新审批链（§4.4），否则 `50011`；红线版留存。 |
| **提前终止** | `TERMINATED(BREACH)`，违约金条款计算，分配按"已到账部分"重算（历史明细保留，冲正记录 `status=REVERSED`）。 |
| **发明人异议分配** | `DISPUTED`/`HELD(ARBITRATION)` 暂缓发放（§4.12），仲裁裁决后 RESUME 调整再发放。 |
| **到账重复登记** | `bank_flow_no` 部分唯一索引拦截（50008）。 |
| **AI 限流** | 20/min 超阈值返回 `429`（50007）。 |
| **电子签失败** | 供应商异常 `50006`，降级线下签补录（§4.5）。 |

## 9. 非功能与性能（PRD §12）

- **交易列表 < 500ms**：主路径组合索引 `(tenant_id, legal_entity_id, status)`，分页 + 覆盖索引；达梦退应用层缓存。
- **合同 AI 风险审查 < 10s**：svc-ai-gateway 异步流式，前端"逐条出"；召回率 ≥ 85%（PRD §8.2）。
- **公示页 CDN**：`GET /publicity/{dealId}` 走 CDN 边缘缓存 + 快照哈希，公开访问抗压。
- **交易记录不可篡改 / 哈希链**：`T_CONTRACT.immutable_hash + prev_hash` 版本链；关键动作写 `sys_audit_log`（字段级 diff + `prev_sig/sig` 哈希链）；端到端链落 `e_trace_node`（披露→交易→合同→到账→分配）。
- **数据保留**：交易合同 `contract_file_url` **永久保留**；公示记录 + `public_snapshot_hash` 保留 **10 年**（PRD §12）；分配规则历史版本 `SUPERSEDED` 留档可复算。
- **可复算**：审批门槛与分配命中记 `sys_rule_hit` + `policy_pack_id` 快照，支持审计逐笔复算。
- **幂等/限流**：写操作 `Idempotency-Key`；普通 100/min、AI 20/min。
- **合规**：满足《促进科技成果转化法》（2021 修订）第 27 条公示要求与年度披露（§4.8/`/annual-report/generate`）。

## 10. 待细化问题（定稿前须闭环）

1. **公示与电子签次序**：PRD 端到端流程"电子签→公示"，§6.2 状态机为 `APPROVED→PUBLICIZED→SIGNED→EXECUTING`（先公示后生效签署）。本设计以状态机为准并将次序配置化（`deal.signed` vs `publicity.completed` 的先后开关），需业务/法务确认法定流程口径。
2. **T 表 code 前缀登记**：`T_DEAL` 用已登记 `DEAL`；其余 T 表（披露/合同/到账/分配/公示/年报/企业库）PRD 2.11 尚未登记前缀。定稿前须向 `seq_prefix_registry` 申请（建议 DIS/CTR/INC/DST/PUB/AR/EP 等）并回填生成逻辑。
3. **国家技术转移平台对接协议**：T-05 挂牌推送字段映射、鉴权与回执机制待对接文档确认。
4. **评估机构对接方式**：T-04 上传 API vs 邮件解析（PRD §10）二选一或并存；外评报告结构化字段抽取精度待定。
5. **销售提成上报口径**：企业上报销售额的数据源（对账文件/API/人工）、审计核验与提成争议处理流程待细化（§4.6）。
6. **作价入股退出估值**：退出触发时的重新评估与工商/税务联动责任主体待定（§4.11）。
7. **AI 定价/机会识别合规护栏**：置信度阈值、免责标注、结果留存周期，以及"仅供参考不硬约束"的系统级校验点待定（§4.9）。
8. **达梦适配**：部分唯一索引、JSONB、pg_trgm/GIN、`COALESCE` 表达式唯一索引的替换见 `./README.md` §2.4，需 DBA 出具达梦变体脚本。
