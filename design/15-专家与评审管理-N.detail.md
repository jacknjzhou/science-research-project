## 2. 数据表（对齐 DDL）

- **n_expert**：专家主档。通用列 + `security_level`。业务列 `name/gender/title/education/org_name/dept/phone/email/user_id(逻辑→sys_user 可空=纯外部)/source(INTERNAL/EXTERNAL)/field_tags(JSONB 数组)/expertise_level/avoid_orgs(JSONB)/avoid_person_ids(JSONB)/bank_account(加密治理)/cv_doc_ids/last_review_at/review_count`。状态 `CANDIDATE/ACTIVE/SUSPENDED/BLACKLIST`。唯一 `uk_n_expert_code(tenant_id,code) WHERE deleted=0 AND code IS NOT NULL`；索引 `(tenant_id,status)`、`field_tags GIN`、`user_id`。
- **n_expert_group**：专家分组/遴选池（轻量）。`name/criteria(JSONB)/expert_ids(JSONB)`。唯一 `uk_n_group_name(tenant_id,name) WHERE deleted=0`。（本轮从简，DDL 保留，端点未开。）
- **n_review_task**：评审任务/事件。通用列 + `code(RVW-年-序)/security_level`。业务列 `biz_type(MID_CHECK/FINAL_ACCEPT/OUTPUT_EVAL/PROJECT_APPLY/OTHER)/target_type/target_id(逻辑外键)/project_id(回避判定)/title/review_method(RANDOM/COMBINATION/MANUAL)/plan_count/draw_rule(JSONB)/conclusion/score_summary(JSONB)/drawn_at/started_at/concluded_at`。
- **n_review_invitation**：抽取/邀请名单。`task_id→n_review_task`、`expert_id→n_expert`、`seat_no`、`avoid_hit`（回避命中审计）、`response(PENDING/ACCEPT/DECLINE/EXPIRED)`。唯一 `uk_n_invite(task_id,expert_id)`。
- **n_review_score**：在线打分。`task_id`、`expert_id`、`dimension_scores(JSONB [{dim,score,max}])`、`total_score NUMERIC(10,2)`、`comment`、`status(SUBMITTED/ABSTAIN)`。唯一 `uk_n_score(task_id,expert_id)`。
- **n_review_fee**：评审费（联动 F）。`task_id`、`expert_id`、`amount NUMERIC(18,2)`、`pay_channel`、`status(UNPAID/PAID)`、`paid_at`、`voucher_code`。唯一 `uk_n_fee(task_id,expert_id) WHERE deleted=0`。

## 3. 评审任务状态机

`DRAFT → DRAWN → INVITING → QUORUM → IN_REVIEW → COLLECTING → CONCLUDED`；分支 `CANCELLED`。

- `DRAFT→DRAWN`：抽取引擎命中名单，落 `n_review_invitation(response=PENDING)`，回避者 `avoid_hit=true`。
- `DRAWN→INVITING`：发出邀请（`biz_type=MID_CHECK` 时经 E 导出方法回填拟邀专家 user_id）。
- `INVITING→QUORUM`：`CountAccepted` 达 `plan_count` 法定人数。
- `QUORUM→IN_REVIEW`：`start`。
- `IN_REVIEW→COLLECTING`：已接受专家全部提交打分（`CountScores==accepted`）。
- `COLLECTING→CONCLUDED`：`conclude` 汇总 `score_summary` 并回写 E/R。
- `→CANCELLED`：`cancel`。

## 4. 抽取引擎（回避 + 确定性）

`POST /reviews/{id}/draw`：

1. 读 `n_expert(status=ACTIVE, deleted=0)` 构造候选池（解析 `field_tags`）。
2. 回避集：`draw_rule.exclude_user_ids/exclude_orgs` ∪ 项目成员/PI（`project_id`）∪ 专家自身 `avoid_orgs/avoid_person_ids`。
3. 领域匹配：`draw_rule.field_tags` ∩ 候选 `field_tags`。
4. 过滤不可回避对象后，洗牌取 `plan_count`。随机使用注入 seed（缺省 `time.Now().UnixNano()`，测试传固定 seed）——**确定性可复现**，不用全局 rand。
5. `org_diversity` 时按单位去重优先，不足回填。
6. 落 `n_review_invitation`（seat_no 排序），回避命中者记 `avoid_hit=true` 供审计；任务 → `DRAWN`。

## 5. 端点（tag: expertreview）

专家库：`GET/POST /experts`、`GET/PUT/DELETE /experts/{id}`、`POST /experts/{id}/status`。
评审与抽取：`GET/POST /reviews`、`GET/DELETE /reviews/{id}`、`POST /reviews/{id}/draw|invite|accept|decline|start|scores|conclude|fees`、`GET /reviews/{id}/detail`。
列表端点 `data` 用自包含 typed PageResult（base `PageResult{total,page,size}` + 端点内 `allOf` 覆写 `list` 项型），与 M 模块同款，规避 R/S pinned PageResult 组合冲突。

## 6. 回写 E/R（跨模块写，经被写模块单一写者导出方法）

N 通过 `*project.Handler`、`*output.Handler` 调用：

- `SetMidCheckExperts(ctx, midCheckID, expertUserIDs)` — 邀请接受后回填 `E_MID_CHECK.expert_ids`（仅 biz_type=MID_CHECK）。
- `ConcludeMidCheck(ctx, midCheckID, projectID, conclusion, scoreDetail)` — 中检结论 + 驱动 `E_PROJECT.status`。
- `ConcludeFinalAccept(ctx, finalAcceptID, status)` — 结题技术轨结论（APPROVED/REJECTED/NEED_SUPPLEMENT）。
- `ConcludeOutputEval(ctx, outputID, pass bool)` — 成果评价回写 `R_OUTPUT.status/is_claimed`（conclusion=="PASS"→true）。

映射：`biz_type=MID_CHECK→ConcludeMidCheck`；`FINAL_ACCEPT→ConcludeFinalAccept`（PASS→APPROVED/REJECT→REJECTED/SUPPLEMENT→NEED_SUPPLEMENT）；`OUTPUT_EVAL→ConcludeOutputEval`。
