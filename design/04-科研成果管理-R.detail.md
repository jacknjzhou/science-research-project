## 2. 服务与分层

微服务划分（一模块一库，跨库只存对方 `id`，一致性走 Kafka 事件）：

```
svc-output（R 主服务）
├─ interfaces  : REST（04-...openapi.yaml）/ DTO / Assembler
├─ application : 认领编排、状态机驱动、批量操作、导出、幂等
├─ domain      : R_OUTPUT 聚合根 + 各 *_EXT 实体值对象 + 规则策略（阈值/绩效/年费）
└─ infra       : PG(15) 仓储、Kafka 生产/消费、ES 检索索引、对象存储附件

svc-integration-pub（外部数据源抓取管道）
├─ connector   : WoS(clarivate)/Scopus(elsevier)/CNKI/万方/CNIPA(专利局)/Crossref/Altmetric
├─ pipeline    : 每日增量抓取 → 作者名解析（拼音/中文名/单位）→ 归一化 → 投递匹配
└─ degrade     : 数据源不可用时降级为手动录入 + 增量补抓

svc-ai-gateway（AI 中台，被 svc-output 调用）
├─ match       : 编辑距离 + 拼音 + 单位 的作者匹配，SimHash + 语义向量 去重
├─ fill        : LLM + Crossref/专利局 组合查询（R-15）
├─ dedup       : 全文查重 + 图片 pHash + 表格异常（R-19）
└─ predict     : 引用曲线/影响力预测（R-16，软标签，不入绩效硬指标）

svc-mdm（主数据）
└─ 提供 sys_dict（成果类型/分区/法律状态可配）、sys_org（单位）、sys_user（作者库）读取
```

分层约束：`interfaces` 不触库；`domain` 不依赖框架；`infra` 实现仓储与适配器；跨模块联动（关联项目推荐、回流 S 画像）一律通过事件解耦。

## 4. 关键业务规则

### 4.1 成果状态机迁移表

状态 token 见 `./README.md` §4。迁移矩阵（`R_OUTPUT.status`）：

| 当前态 \ 动作 | 抓取入库 | 匹配推送 | 认领 | 关联项目 | 绩效计入 | 手动录入 | 送审 | 审核通过 | 审核拒绝/标记非本人 |
|----|----|----|----|----|----|----|----|----|----|
| AUTO_FETCHED | — | →PENDING_CLAIM | | | | | | | →REJECTED |
| PENDING_CLAIM | | — | →CLAIMED | | | | | | →REJECTED |
| MANUAL_DRAFT | | | | | | — | →PENDING_REVIEW | | |
| PENDING_REVIEW | | | →CLAIMED | | | | — | →CLAIMED | →REJECTED |
| CLAIMED | | | — | →ASSIGNED_TO_PROJECT | | | | | |
| ASSIGNED_TO_PROJECT | | | | — | →COUNTED_FOR_PERFORMANCE | | | | |
| COUNTED_FOR_PERFORMANCE | | | | | — | | | | |
| REJECTED | 终态（可复议） | | | | | | | | |

非法迁移一律拒绝并返回业务错误；每次迁移写 `sys_audit_log`（object_type=`R_OUTPUT`）。

### 4.2 抓取 → 解析 → 匹配 → 认领闭环

```
外部源 → 增量抓取(svc-integration-pub)
      → 元数据落 AUTO_FETCHED + 记录 source
      → 作者名解析（拼音/中文名/单位规范化）
      → 与本院用户库比对（工号 + ORCID 双主键）
      → R-04 智能匹配打分 → 按置信度分派（见 4.3）
      → 高置信入 PENDING_CLAIM，投递"待认领中心"
      → 用户 CLAIM/REJECT/MARK_NOT_MINE
      → 认领后 output.claimed → 关联项目推荐（见 §5）→ ASSIGNED_TO_PROJECT
      → 绩效规则引擎判定 → COUNTED_FOR_PERFORMANCE
```

匹配反馈（MARK_NOT_MINE / 误召）回流训练，闭环提升召回率与准确率。

### 4.3 R-04 智能匹配阈值

| 置信度区间 | 处置 | 状态 |
|------------|------|------|
| **> 0.95** | 自动推送至用户"待认领" | AUTO_FETCHED → PENDING_CLAIM |
| **0.7 ~ 0.95** | 标记可疑，需人工/管理员复核 | PENDING_CLAIM + claim_status=DOUBTFUL |
| **< 0.7** | 只入外部成果池，不打扰用户 | AUTO_FETCHED（claim_status=UNCLAIMED，不入待认领） |

评估口径：准确率 ≥ 90%，误召率（点"这不是我"比例）≤ 5%，召回率 ≥ 85%。算法：作者名模糊匹配（编辑距离 + 拼音 + 单位）+ 标题去重（SimHash + 语义相似度）。

### 4.4 SimHash + 语义去重与合并仲裁

- **入库前查重**：新抓取记录计算 `simhash` 与规范化 `title_hash`；`(tenant_id,title_hash) WHERE deleted=0` 命中即视为疑似重复。
- **两级判定**：SimHash 汉明距离 ≤ 阈值 → 疑似；再经语义向量相似度复核（>0.95 判为重复）。
- **合并仲裁**：确认为重复时，**保留主记录**（信息最全/最早 CLAIMED 者），其余记录置 `master_output_id=主记录id` 并软合并（不物理删除，保留来源可追溯）。认领、指标、绩效只在主记录聚合，避免重复计入。
- 冲突字段（作者顺序/单位归属歧义）走管理员仲裁。

### 4.5 专利年费到期通知与超期放弃

- 管道每日扫描 `R_PATENT_EXT.annuity_due_date`，在到期前 **60 / 30 / 7 天** 分级生成 `patent.annuity.due` 事件，通知发明人与专利管理员（送达率 100%）。
- 逾期 **30 / 60 / 90 天** 分级升级通知。
- 超 **90 天** 未缴 → 进入**放弃流程**，需 PI 确认后方可将 `legal_status` 置 `ABANDONED`；系统不自动放弃（防止误操作导致专利失效）。
- 法律状态变化（无效等）由专利局数据源同步 → `legal_status=INVALID`，UI 显著标红，停发年费提醒。

### 4.6 共同通讯多值与绩效分配规则可配

- `authors` JSONB 支持多个 `is_corresponding=true`（共同通讯）；每人携 `share_pct` 份额。
- 绩效计入（R-11）由 `sys_policy_pack` 规则引擎判定"哪些类型计入、按何标准计分、共同作者如何分配"，命中记 `sys_rule_hit`（可解释、可复算），`R_OUTPUT.policy_pack_id` 落快照。
- 分配规则**可配**，不同法人（legal_entity_id）可挂不同制度包。

### 4.7 单位署名歧义走管理员仲裁

同一论文多个本院作者、作者归属与单位绩效冲突时（PRD §11），不做自动裁决：投递至管理员仲裁队列，仲裁结论写 `R_CLAIM_RECORD.EDIT` + `affiliations` 修订，全程留审计。

### 4.8 规则引擎 vs LLM 分工

| 能力 | 实现方 | 说明 |
|------|--------|------|
| 影响因子 / 分区自动更新（R-12） | **数据管道** | JCR/中科院分区年度刷新 + 引用日增量，确定性数据同步 |
| 高被引 / ESI 打标（R-17） | **数据管道 + 阈值规则** | 基于 WoS 学科分位数阈值 |
| 语义查重 / 影响力预测（R-16/R-19） | **模型（LLM/向量）** | 相似度、引用曲线预测为软标签，不作绩效硬指标 |
| 作者智能匹配（R-04） | **模型 + 规则混合** | 打分模型出置信度，阈值分派由规则决定 |
| 绩效计入（R-11） | **规则引擎** | 制度包 DSL 判定，可复算可审计，绝不由 LLM 直接决定 |

原则：**确定性计算交管道/规则引擎，模糊判断交模型，价值裁决（绩效/放弃）交规则引擎 + 人工**。

## 5. 事件契约（内部 Kafka）

命名 `domain.action`，value 必带 `{ eventId, eventType, occurredAt, tenantId, legalEntityId, traceId, payload }`（`./README.md` §3.1）。

### 5.1 output.claimed
```json
{ "eventId":"...", "eventType":"output.claimed", "occurredAt":"...",
  "tenantId":1, "legalEntityId":10, "traceId":"...",
  "payload":{ "outputId":123, "userId":456, "outputType":"PAPER",
              "titleHash":"...", "matchConfidence":0.97, "batchId":"b-..." } }
```
消费方：
- **关联项目推荐**：按作者 + 时间窗推荐可归属 `E_PROJECT`，引导用户完成 `ASSIGNED_TO_PROJECT`（R-10）。
- **回流人员画像（联动 S 模块）**：认领结果与作者份额回写 `S_STAFF` 成果画像，供考核/统计。

### 5.2 output.matched
```json
{ "eventType":"output.matched",
  "payload":{ "outputId":123, "candidateUserIds":[456,789],
              "confidence":0.82, "tier":"DOUBTFUL", "source":"WOS" } }
```
触发"待认领中心"通知（>0.95 直达用户，0.7~0.95 进复核队列）。

### 5.3 patent.annuity.due
```json
{ "eventType":"patent.annuity.due",
  "payload":{ "outputId":888, "applicationNo":"CN2023...", "annuityDueDate":"2026-10-01",
              "stage":"DUE_60", "inventorUserIds":[...], "managerUserIds":[...] } }
```
`stage ∈ DUE_60/DUE_30/DUE_7/OVERDUE_30/OVERDUE_60/OVERDUE_90`；驱动 60/30/7 天与逾期分级通知。

### 5.4 paper.cited.updated
```json
{ "eventType":"paper.cited.updated",
  "payload":{ "outputId":123, "snapshotDate":"2026-08-14", "citedTimes":42,
              "altmetric":180, "impactFactor":6.5120, "isHighlyCited":true } }
```
消费方：写 `R_METRIC_SNAPSHOT` 当日快照，刷新 `R_PAPER_EXT.cited_times/is_highly_cited`。

| POST | `/output/export` | 成果报送导出（R-18） | 写审计 |

> POST/PUT 均携 `Idempotency-Key`；分页统一 `page`(1-based)+`size`(默认 20/上限 200)；限流普通 100/min、AI 20/min（`429`）。详见 `04-科研成果管理-R.openapi.yaml`。

## 7. 权限与隔离

在 PRD §9 权限矩阵（R-STAFF/R-MANAGER/R-AUDITOR/R-LEADER/R-ADMIN）基础上，补充可见性与密级规则：

- **专利申请中（legal_status=PENDING/EXAMINING/SUBSTANTIVE）**：仅发明人（`inventors.user_id`）与专利管理员可见，其他人不可检索标题。
- **已授权（GRANTED）**：公开元数据，全院可读。
- **涉密成果（security_level=SECRET/TOP_SECRET）**：走单独权限通道，与三员分立账号（`sys_admin_duty`）联动；跨密级域上下行经 `x_flow_audit`（前缀 EXF）留痕。列表/详情/导出/打印一律密级过滤。
- **学术不端核查结果（R-19 ai-dedup）**：`DedupResult.visible_to ∈ {ETHICS, ADMIN}`，仅纪检与管理员可见，普通角色查询被 `403` 拦截。
- **数据隔离**：所有查询强制注入 `tenant_id`（总院法人边界）+ `legal_entity_id`（法人细分）；主路径索引 `(tenant_id, legal_entity_id, status)` 保障隔离下检索性能。

## 8. 异常与边界

| 场景 | 处理 |
|------|------|
| **同名学者** | 匹配以 **工号(staff_no) + ORCID 双主键** 判定，仅姓名命中不认领（R-USR-03 提示"可能是你可能不是你"）。 |
| **姓名变更** | 改名后按 user_id 稳定关联，历史成果自动重关联；旧名进入名曾用名集合参与匹配。 |
| **跳槽 / 单位变更** | 原单位保留其在职期间历史成果（affiliations 冻结快照），新单位归属不追溯覆盖。 |
| **抓取失败** | 数据源不可用时降级：提示手动录入 + 记录补抓队列，恢复后增量补抓。 |
| **作者挂名** | 认领时可 REJECT/MARK_NOT_MINE 并说明理由，进入诚信记录（R_CLAIM_RECORD.reason）。 |
| **专利无效** | 专利局数据源同步 legal_status=INVALID，UI 标红，停发年费提醒。 |
| **年费逾期** | 30/60/90 天分级通知，超 90 天进入放弃流程需 PI 确认（见 4.5）。 |
| **重复入库** | SimHash 命中重复时管理员仲裁保留主记录，其余合并（见 4.4）。 |
| **共同通讯歧义** | 多通讯/单位归属冲突走管理员仲裁（见 4.7）。 |

## 9. 非功能

- **检索性能**：成果搜索响应 < 500ms @ 10 万条（GIN/trigram 标题 + JSONB authors + 主路径组合索引；达梦退 ES）。
- **抓取管道**：支持 100 万条总量、10 万条/月增量；4+ 数据源每日增量 < 4 小时完成。
- **批量认领**：100 条 < 3s（批量接口 + 单事务分片 + 幂等键）。
- **数据质量**：字段完整率 ≥ 95%（DOI/分区/影响因子等关键字段）；分区与影响因子每年自动刷新一次。
- **匹配质量**：召回率 ≥ 85%，准确率 ≥ 90%，误召率 ≤ 5%。
- **送达**：专利年费到期前 3 次通知 100% 送达。
- **合规**：数据源许可协议（license）记录在案，避免爬虫违规；涉密成果单独权限通道。
- **可复算**：绩效计入命中 `sys_rule_hit` + `policy_pack_id` 快照，支持审计复算。
