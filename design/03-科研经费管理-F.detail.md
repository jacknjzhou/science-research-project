### 1.2 依赖关系

- **上游依赖**：
  - `E_PROJECT`（02 E）：`project_id` 逻辑引用；项目状态（EXECUTING/CLOSED）约束预算执行与决算触发。
  - `G_CONTRACT`/`G_SUPPLIER`（09 G）：F-22 外拨联动合同金额上限与外协主体（`contract_id`/`outsource_unit_id`）。
  - `A_ASSET`（10 A）：A-12 折旧分摊经事件回灌 `F_COST_POOL.indirect_alloc_json`。
  - `S_STAFF`/`sys_user`（07 S / common）：报销人、审批人、认领人（`*_user_id`/`staff_id`）；离职状态驱动审批流转办。
  - `sys_policy_pack`/`sys_rule_hit`（common）：制度规则引擎，预算比例/科目约束/外拨限额/绩效限额/审批权限矩阵的确定性判定；关键表落 `policy_pack_id` 快照供复算。
  - `sys_dict`（common）：`expense_type`/科目类别/结余处理等下拉，禁止硬编码（PRD 2.8）。
  - `seq_prefix_registry`/`seq_allocation`（common）：`svc-numbering` 分配 BUD/EXP/DISB 号段。
  - `sys_print_template`（common）：报销凭证套打 `EXPENSE_VOUCHER`（PRD 2.14）。
- **下游/被依赖**：`D`（08 数据分析）订阅 F 事件构建大屏/画像；`X`（11 涉密）参与 `security_level` 读写过滤。

### 1.3 里程碑边界

M1 交付全部 P0（F-01..F-14、F-21、F-22）+ 全成本 F-20 + 大屏 F-18 只读骨架 + AI 建议类 F-15/F-16/F-17。F-19（AI 决算报告）P2 仅预留 `audit_report_url`/生成钩子，模型编排延后 M2。涉密外拨的跨域审批流（→X `x_flow_audit`）在 M1 仅落 `security_level` 标记，流程能力 M2 完善。

## 2. 服务与分层

```
                       svc-gateway（鉴权/限流/多租户注入/traceId）
                                    │
        ┌───────────────────────────┼───────────────────────────┐
        ▼                           ▼                           ▼
  svc-funding(F)              svc-policy(Drools)         svc-workflow(Camunda)
   领域/应用/基础设施           制度包执行·命中留痕          多级审批编排/转办/加签
        │                           ▲                           │
        ├── svc-numbering ──────────┘（BUD/EXP/DISB 取号）       │
        ├── svc-ai-gateway（OCR/发票合理性/预测，只回吐建议）     │
        ├── svc-integration-bank（流水导入/回执）                 │
        ├── svc-integration-tax（发票查验·税总）                  │
        ├── svc-integration-fin（凭证下发/回调 F-11/F-21）        │
        └── svc-audit / svc-print / svc-file / svc-mdm ──────────┘
```

### 2.1 svc-funding（业务主服务）

DDD 四层：
- **接口层（Adapter）**：REST Controller（对应 OpenAPI 38 个 operation）、Kafka Consumer（`expense.approved`/`income.claimed`/A 折旧事件/G 付款回调）、定时任务（执行率预测日切、计提批量、流水匹配）。
- **应用层（Application）**：用例编排 + 事务边界（`@Transactional`）+ 幂等（`Idempotency-Key`）+ 权限二次校验（ABAC：`legal_entity`/`security_level`）。关键用例：`BudgetSubmitUseCase`、`ExpenseSubmitUseCase`（含 F-10 冻结）、`ApprovalUseCase`（含解冻/扣减）、`VoucherSyncUseCase`、`DisbursementCreateUseCase`（G 合同联动）、`ParallelBookkeepUseCase`（F-21）。
- **领域层（Domain）**：聚合根 `Budget`（含 `BudgetLine` 值对象集合）、`Expense`（含 `Invoice` 引用）、`Disbursement`、`CostPool`、`AccountingEntry`；领域事件、状态机守卫（见 §4.1 迁移表）、不变式（余额守恒、借贷平衡、三重指纹唯一）。
- **基础设施层（Infrastructure）**：MyBatis-Plus 仓储（屏蔽 PG/达梦方言，TECH_ARCH §二）、Redis（余额热点缓存/号段/幂等缓存）、Kafka、MinIO、ClickHouse 只读投影 DAO。

### 2.2 svc-policy（确定性判定，规则引擎）

**唯一职责**：限额/科目/比例/越权/审批权限矩阵的**确定性、可解释、可复算**判定（PRD 2.10）。执行 `sys_policy_pack.dsl_yaml`（Drools），返回 `{ ruleCode, clauseRef, verdict(PASS/REJECT/WARN), detail }`，落 `sys_rule_hit` + 业务表 `policy_pack_id` 快照。F 侧调用点：
- 预算编制/调整：科目比例上限（设备费≤30%、间接费≤20% 等）、包干制禁拆科目。
- 报销提交：科目可用性、超支软/硬阈值（§4.3）、劳务费≤当月工资 40%。
- 外拨：合同剩余可拨额上限、禁止整体转包/单一来源未说明/关联外协单位。
- 绩效计提：间接费率阶梯与绩效限额。
- 审批路由：金额阈值 → 审批权限矩阵（<10 万→科研管理员，≥10 万→院所领导）。

### 2.3 svc-integration（适配层，出向）

| 子服务 | 对端 | 协议 | 一致性 | F 用例 |
|--------|------|------|--------|--------|
| svc-integration-bank | 6 大行银企直连/文件 | REST/文件 | 幂等（`bank_flow_no`）+ 日终对账 | F-05/F-06 流水导入与匹配 |
| svc-integration-tax | 税务发票查验平台 | REST 同步 | 失败重试 + 待查验挂起 | F-08/F-15 发票验真 |
| svc-integration-fin | 用友/金蝶/浪潮 + 政府会计平台 | REST + 对账文件 | Saga + 日终对账 | F-11 凭证同步 / F-21 平行记账下发 |

### 2.4 svc-ai-gateway（概率性判断，只回吐建议）

发票内容合理性（LLM）、执行率预测（Prophet/LSTM）、OCR 结构化。约束：AI 永不直写业务库；输出必带 `confidence`，低于阈值（默认 0.85）回落人工；不作唯一决策依据（PRD 2.4）。F-15/F-16/F-17/F-19 经此服务。

### 2.5 svc-numbering（统一编号）

BUD/EXP/DISB 取号唯一入口，Redis+DB 双写，`{prefix}-{yyyy}-{seq6}`，支持法人短码分号段（`per_entity=TRUE`）。作废不回收、重试幂等（PRD 2.11）。业务代码禁止自造号。

## 4. 关键业务规则

### 4.1 报销状态机迁移表（PRD §6.3 / README §4）

token 序列：`DRAFT/SUBMITTED/AI_REVIEW/HUMAN_REVIEW/APPROVED/REJECTED/RETURNED/PAID/VOUCHER_SYNCED`。守卫条件由 `svc-funding`（领域）+ `svc-policy`（合规）+ `svc-workflow`（审批）共同裁决。**任何迁移均在同一本地事务内完成相应预算冻结/扣减/释放**（见 §4.2）。

| 当前态 | 动作（触发方） | 迁移后态 | 守卫/副作用 |
|--------|----------------|----------|-------------|
| DRAFT | 提交（PI） | SUBMITTED | 三重指纹查重通过；svc-policy 科目/限额 PASS/WARN；**冻结 `amount_frozen += amount`**；发 `expense.submitted` |
| SUBMITTED | AI 初审放行（svc-ai-gateway） | AI_REVIEW→HUMAN_REVIEW | 税总查验 & 内容合理性；`ai_confidence≥0.85` 直接进人工队列 |
| SUBMITTED | AI 判定可疑/低置信 | HUMAN_REVIEW（转人工） | `verdict=REVIEW/REJECT` 或 confidence<0.85；附 issues；不自动拒绝 |
| SUBMITTED | 查验未回 | HUMAN_REVIEW + `invoice_check_status=PENDING` | 允许先提交标记待查验；48h 未成功转人工（§8） |
| AI_REVIEW | svc-policy 硬拦截（超限/越权） | RETURNED | **释放冻结 `amount_frozen -= amount, amount_released += amount`**；回传规则号+条款 |
| HUMAN_REVIEW | 逐级同意（负责人→[<10万:管理员 / ≥10万:领导]→财务复核） | HUMAN_REVIEW（步进） | 每步落 `F_EXPENSE_APPROVAL`；金额阈值路由由 svc-policy 权限矩阵决定 |
| HUMAN_REVIEW | 出纳付款（财务复核通过） | APPROVED→PAID | **`amount_frozen -= amount` 且 `amount_used += amount`（原子冻结转实扣）**；发 `expense.approved` |
| APPROVED/PAID | 凭证同步成功回调 | VOUCHER_SYNCED | `F_VOUCHER_SYNC.sync_status=SUCCESS`，回填 voucher_no；生成 F-21 双分录 |
| HUMAN_REVIEW | 拒绝 | REJECTED（终态） | **释放冻结**；通知 PI |
| HUMAN_REVIEW | 退回补充 | RETURNED | **释放冻结**；PI 修改后回 DRAFT 再提交 |
| PAID | 冲销（红字） | 经新单冲销 | 凭证不可改，只冲销（§7）；冻结/扣减反向分录 |

> `RETURNED`/`REJECTED` 回 DRAFT 重提交时必须重新冻结并重新查重，防止重复占用或漏占。审批人离职 → `DELEGATE` 自动流转（§8）。

### 4.2 预算冻结与余额扣减一致性（F-10）

不变式（对每行 `F_BUDGET_LINE` 恒成立）：
```
remaining = amount_planned + amount_adjusted - amount_frozen - amount_used - amount_released ≥ 0
```
规则：
1. **提交即冻结**：`ExpenseSubmitUseCase` 在同一 DB 事务内 `SELECT ... FOR UPDATE` 锁行 → 校验 `remaining ≥ amount` → `amount_frozen += amount`。并发报销不会超卖（悲观行锁 + Redis 余额预热仅做前端提示，不落账）。
2. **付款实扣**：出纳付款原子执行 `amount_frozen -= amount; amount_used += amount`，二者同事务，杜绝"既冻结又实扣"双计。
3. **驳回/退回/拒绝释放**：`amount_frozen -= amount; amount_released += amount`，使后续 `remaining` 恢复。
4. **包干制**：无 `budget_line_id` 时冻结记在预算总额维度（虚拟汇总行），仅校总额不校科目；余额守恒同样成立。
5. **幂等**：冻结/扣减/释放以 `expense_id + 迁移事件` 为幂等键，Kafka 重投不重复扣减（本地事务表去重）。
6. **对账**：日终任务校验 `Σ(used+frozen) ≤ planned+adjusted`，不平则告警并锁行人工介入。

### 4.3 超支软警告 / 硬拦截分级（PRD §11）

以 `本次 amount` 叠加后与 `remaining` 比较，比值 `overRatio = (amount - remaining)/remaining`：
- `overRatio ≤ 0`：PASS（svc-policy）。
- `0 < overRatio ≤ 5%`：**SOFT_WARN** `WARN`，允许提交但强制填写超支说明，进入人工审批重点提示。
- `overRatio > 5%`：**HARD_BLOCK** `REJECT`，迁移到 `RETURNED`，不可提交。
- 阈值 5% 取自 `sys_policy_pack`（可按院所配置），落 `policy_pack_id`；命中记 `sys_rule_hit`。

### 4.4 发票三重指纹查重（PRD §11）

指纹 = 归一化(`发票号` + `金额` + `开票日期`)，对 `(tenant_id, fingerprint_hash)` 建**唯一部分索引**（`WHERE deleted=0`）。创建/提交报销时命中历史 → `F_INVOICE.is_duplicated=TRUE` 且报销 `POST /expenses` 返回 **409 DuplicateInvoice**，直接拒绝。要素归一：发票号去空格大写、金额取价税合计两位小数、日期取 `issue_date`。多张发票场景以主发票要素计算 `fingerprint_hash`，其余发票逐张校验历史唯一性。

### 4.5 F-21 平行记账双分录（《政府会计制度》）

一笔纳入核算范围的现金/权责业务，同时生成两套分录并存 `F_ACCOUNTING_ENTRY`：
- **财务会计（权责发生制）** `fin_entry_json`：确认费用/收入发生（借：业务活动费用/库存物品…，贷：零余额账户用款额度/应付…），**借贷必平衡**（∑借=∑贷）。
- **预算会计（收付实现制）** `bud_entry_json`：仅在**实际收付款**时登记（借：事业支出/行政支出，贷：资金结存/零余额账户用款额度），非现金业务不产生预算分录。
- **过账与同步**：`posted_finance`/`posted_budget` 分别标记；凭证经 `voucher_sync_id` 走 F-11 下发财务系统。
- **两账勾稽**（`reconcile_status`）：按业务规则比对两账金额与要素：
  - `BALANCED`：勾稽平衡 → 正常过账。
  - `UNRECONCILED`：未到勾稽时点（如已确认费用未付款）。
  - `SUSPENSE`：**不平则挂账并告警**，状态 `status=SUSPENSE`，推送财务介入，不阻断业务但阻断期末结账。
- 触发点：`expense.approved`（PAID）、`income.claimed`、A-12 折旧事件、外拨 PAID 回调。幂等键 `(source_txn_type, source_txn_id, period)` 唯一。

### 4.6 F-22 外拨联动 G 合同金额上限拦截

`DisbursementCreateUseCase` 创建前调用 `POST /disbursements/check-contract` 拉取 `G_CONTRACT` 合同额快照（`contract_amount`）与已拨累计（`disbursed_before`，含本模块历史 `F_DISBURSEMENT` 累计）：
```
remain_contract_amount = contract_amount - disbursed_before
若 amount > remain_contract_amount → svc-policy 硬拦截（422 RuleRejected）
```
- 命中合规规则（整体转包、单一来源未说明、外协单位与收款人关联）写入 `compliance_flags`，`HIGH` 级强制转人工+审计。
- 跨模块一致性：外拨 `PAID` → 发事件通知 G 更新合同执行额（Saga，`contract_id` 只存 id，不跨库强事务）；G 付款回调驱动 `voucher_status` 与状态机 `SUBMITTED→APPROVED→PAID→VOUCHER_SYNCED`。
- `security_level`：横向涉密外拨打标，读写经网关 + 数据层双重过滤（PRD 2.13）。

### 4.7 F-20 全成本 = 直接费用 + Σ间接分摊（可复算）

```
full_cost = direct_cost + Σ indirect_alloc_json[].amount
direct_cost = Σ(报销支出 F_EXPENSE.PAID + 外拨 F_DISBURSEMENT.PAID + 采购分摊 A/G)
间接分摊项：管理费/房屋/水电气/设备折旧/共用平台；设备折旧来自 A-12 事件
```
- 每项分摊记录 `basis`（分摊依据，如"按工时/面积/收入占比"）+ `amount`，并落 `policy_pack_id` + `basis_rule_id`，确保**可解释、可复算**（svc-policy 重跑命中规则即可复现金额）。
- 期间 `period` 维度幂等 `(tenant_id, project_id, period)` 唯一。

### 4.8 F-12 绩效支出按到账比例计提并限额

```
绩效可计提上限 = actual_income(实际到账) × performance_rate(制度包限额比例)
本次 performance_amount ≤ 上限 - 已计提累计
```
- **基数是"实际到账"而非"预算"**（PRD §11），未到账不计提。
- 间接费用按阶梯费率（svc-policy 依 `policy_pack_id` 计算，过程写 `calc_detail` 供复算）。
- 超出限额 → svc-policy `REJECT`，计提失败并告警。计提 `POSTED` 时生成 F-21 双分录。

### 4.9 规则引擎 vs LLM 分工（PRD 2.10 / 2.4）

| 判断 | 归属 | 输出 |
|------|------|------|
| 科目/金额是否超限、超支阈值、审批权限矩阵 | **svc-policy 规则引擎** | 命中规则号 + 条款出处 + PASS/REJECT/WARN，可复算 |
| 包干制 vs 预算制科目约束、比例上限 | 规则引擎 | 同上 |
| 外拨合同上限、整体转包红线 | 规则引擎（+G 数据） | 上限校验 + 合规 flags |
| 发票**内容**是否属本项目合理支出、拆分嫌疑语义 | **svc-ai-gateway LLM** | 概率判断 + `confidence` + `issues`；**低置信回落人工** |
| 执行率预测、决算报告起草 | LLM | 建议/初稿，不进入硬约束 |

铁律（PRD 2.4）：AI 不改写用户已提交数据；AI 不作为唯一决策依据通过审批；金额/限额/越权**一律走规则引擎**。审批页展示的 AI 建议仅供人工参考，可疑项强制单独处理（不允许批量放行）。

## 8. 异常与边界（PRD §11）

| 场景 | 处理 |
|------|------|
| 发票查验失败 | 允许先提交，`invoice_check_status=PENDING` 标记待查验；**48h 未成功转人工**（`MANUAL`），发提醒 |
| 科目超支 0–5% | 软警告，强制超支说明，进人工重点审批（§4.3） |
| 科目超支 >5% | 硬拦截，迁 `RETURNED`，不可提交 |
| 跨月报销 | 允许，须附加说明（付款与报销期不一致）；影响 F-21 期间归属 `period` |
| 重复报销 | 三重指纹命中 → 409 直接拒绝，`is_duplicated=TRUE` |
| 审批人离职 | 自动流转：`S_STAFF.employment_status=RESIGNED` → `DELEGATE` 至上级或指定备选（`delegateToUserId`），重算审批权限矩阵 |
| 凭证同步失败 | `retry_count` 累加，退避重试 **3 次**；仍失败 `status=MANUAL`，UI 显示"待同步"，进人工重推队列 |
| 包干制 | 隐藏科目字段，仅总额 + 执行率；余额守恒按总额维度 |
| 绩效超限 | 按到账比例计提超限额 → svc-policy REJECT，不生成计提 |
| 两账勾稽不平 | F-21 `reconcile_status=SUSPENSE` 挂账并告警，阻断期末结账不阻断单笔业务 |
| AI 误判 | PI/审批人标记 `F_ANOMALY.false_positive=TRUE`，数据回流训练集（PRD 2.4 数据回流） |
| 幂等冲突 | 重复 `Idempotency-Key` 返回首个结果，不重复冻结/扣减 |
| 号段耗尽/取号超时 | svc-numbering 步长批量预取（`step=100`），DB 双写灾备回灌；取号失败快速失败不产脏数据 |

## 9. 非功能需求

| 维度 | 目标（PRD §12 / TECH_ARCH §十一/§十二） | 手段 |
|------|------|------|
| 报销提交延迟 | **< 500ms** | 余额 Redis 预热 + 本地事务冻结 + 查重走唯一索引 + 异步 AI（提交不等 AI 返回） |
| 发票 OCR | **首字节 < 3s** | svc-ai-gateway 异步/流式，移动端直传对象存储 + 回调 |
| 大屏刷新 | **< 5s** | OLTP→OLAP（ClickHouse）CDC/事件准实时投影，大屏只读 OLAP，不拖垮交易库 |
| 1 万条流水匹配 | **< 60s** | 批量导入 + 并行匹配 + 号段/规则缓存；结果集落 `F_INCOME` |
| 列表查询 | P95 < 500ms，导出 1w < 30s | 组合索引 `(tenant_id,status)`、`project_id`、`budget_line_id`；分页上限 200；异步导出 |
| 安全 | 传输 **TLS 1.3**，敏感字段落库 **AES-256**（税号/账号/金额上下文） | KMS + 列级加密；密钥独立配置中心 |
| 合规 | **等保 2.0 三级** | 三网隔离 + 三员分立 + 字段级审计哈希链 + 二次鉴别 |
| 可用性 | 核心写 99.9% | 多副本 + HPA + 熔断降级 + 主从切换 |
| 一致性 | 跨模块不重不漏 | Kafka + Saga + 本地事务表 + 日终对账 |
| 可审计 | 全动作可复算 | `policy_pack_id` 快照 + 编号幂等 + 审批流水 |
| AI 可控 | 不自动决策 | 置信度阈值 + 人工兜底 + 只产建议 |
| 信创 | 全栈国产化可交付 | 达梦/麒麟/东方通替换；方言经 MyBatis 层屏蔽（见 DDL 顶部注记） |
