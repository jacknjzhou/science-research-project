## 2. 服务与分层

```
                              ┌──────────────────────────────────────────┐
   前端(台账/库存/领用/折旧/盘点)  │                API 网关 /api/v1            │
                              └───────────────┬──────────────────────────┘
                                              │ Bearer JWT / Idempotency-Key / 法人+密级上下文
      ┌───────────────┬──────────────────────┼───────────────────┬──────────────────┐
      ▼               ▼                      ▼                   ▼                  ▼
 svc-asset        svc-policy           svc-integration-fin   svc-ai-gateway     svc-numbering
 (资产/耗材/       (确定性规则引擎：       (凭证下发/过账回写     (A-15 抽取/          (AST/DSP
  流水/处置/        折旧·危化限额·         → F-11、成本分摊)     A-16 异常领用/        号段分配)
  折旧编排·台账)    安全库存·效期·残值)                          A-17 重复购置)
      │               │                      │                   │                  │
      └─────────── Kafka 事件总线 domain.action (到货→建卡 / 折旧完成→凭证+分摊 / 领用出库 / 处置完成) ───────────┘
                              │
                    svc-integration-iot (条码/RFID/门禁采集，预留适配器)
```

**分层约定（各服务同构）**：
- `controller`：参数/幂等/权限校验（法人 + 密级 + 双人确认），DTO ↔ 领域模型转换；OpenAPI 契约落此层。
- `application`：用例编排、状态机驱动、Saga 发起、事务边界；折旧/盘点等批处理用编排器 + 分片。
- `domain`：状态机、规则裁决（调用 svc-policy 结果）、值对象（金额 NUMERIC(18,2)、数量 NUMERIC(18,3)、比例 NUMERIC(6,4)）。
- `infrastructure`：PostgreSQL 15 持久化（达梦差异见 DDL 顶部）、Kafka 生产/消费、对象存储（MSDS/发票）、逻辑外键的跨服务客户端（G/F/E）。

**职责边界**：
- `svc-asset` 是唯一写 A 五表的领域服务；折旧批处理编排在 svc-asset，规则口径来自 svc-policy，凭证落地在 svc-integration-fin。
- `svc-policy` 不做业务落库，只返回确定性裁决结果并写 `sys_rule_hit`（可解释、可复算）。
- `svc-integration-iot` 为适配器（M1 预留接口/表结构占位，不实现实时定位）。

## 3. 数据模型明细

> 全部表含 §2.1 通用列（`id/code/tenant_id/status/deleted/creator_id/modifier_id/created_at/updated_at/remark`）与治理列 `legal_entity_id NOT NULL`、`security_level`；下表只列业务列与关键约束。完整定义见 `10-资产与耗材管理-A.ddl.sql`。

### 3.1 A_ASSET（资产卡，单号 AST-年-序，1 表 1 台/项）

| 列 | 类型 | 说明 |
|----|------|------|
| asset_type | VARCHAR(16) | FIXED/INTANGIBLE（字典 asset_type） |
| category_code | VARCHAR(64) | 资产分类字典编码（sys_dict_item:asset_category，树形） |
| name / brand / model / serial_no | VARCHAR | 名称/品牌/型号/出厂序列号（一物一码） |
| value | NUMERIC(18,2) | 入账原值；缺失→整卡 PENDING_RECEIPT |
| purchase_date / in_date | DATE | 购置/入账启用日期 |
| depr_method / depr_years | VARCHAR(16)/SMALLINT | 折旧方法/年限（policy_pack 可覆盖） |
| depr_accum / net_value | NUMERIC(18,2) | 累计折旧（由 A_DEPRECIATION 回写）/ 净值 |
| custodian_id / dept_id / location | BIGINT/VARCHAR | 责任人 / 存放部门 / 存放地 |
| source_type / source_ref | VARCHAR(16)/BIGINT | 采购·自研·捐赠·调拨 / 来源单据（G_CONTRACT 逻辑引用） |
| project_id | BIGINT | 成本归属项目（E_PROJECT 逻辑引用） |
| usage_rate / share_flag / open_flag | NUMERIC(5,4)/BOOLEAN | 使用率 / 是否共享 / 是否对外开放 |
| policy_pack_id | BIGINT | 折旧政策快照（sys_policy_pack 逻辑引用） |
| status | VARCHAR(32) | 见 §4.1 资产状态机 token |

索引：`uk_asset_code(tenant_id,code) WHERE deleted=0`、`idx_asset_tenant(tenant_id,legal_entity_id,status)`、`idx_asset_proj / custd / dept / serial / cat`。

### 3.2 A_CONSUMABLE（耗材/试剂库存，SKU+批次维度）

sku / name / category（REAGENT·CONSUMABLE·COMPONENT·OFFICE）/ is_hazard / hazard_level / msds_url / stock_qty NUMERIC(18,3) / unit / batch_no / produce_date / expire_date / safe_stock NUMERIC(18,3) / location / custodian_id / status（§4.2 库存状态）。
唯一：`uk_consumable_sku(tenant_id,batch_no,sku) WHERE deleted=0`；效期扫描：`idx_consumable_expiry(sku,expire_date)`。

### 3.3 A_STOCK_TXN（出入库/领用流水，账实底稿）

type（STOCK_IN/STOCK_OUT/REQUISITION/RETURN/RETURN_TO_STOCK/HAZARD_DISPOSE/COUNT_GAIN/COUNT_LOSS，字典 stock_txn_type）/ ref_asset_id（同模块物理 FK A_ASSET）/ ref_sku + ref_batch_no（定位耗材）/ qty NUMERIC(18,3) / amount NUMERIC(18,2) / project_id（E 逻辑）/ operator_id / double_confirm_by（危化第二人）/ related_expense_id（F_EXPENSE 逻辑）/ txn_time / balance_after / fifo_exempt（豁免留痕）/ status（领用状态机 REQUESTED/DOUBLE_CONFIRM/ISSUED）。

### 3.4 A_DEPRECIATION（折旧记录，携带 policy_pack_id）

asset_id（物理 FK A_ASSET）/ period VARCHAR(7) `YYYY-MM` / depr_amount NUMERIC(18,2) / alloc_project_ids JSONB `[{project_id,ratio,amount}]` / voucher_id（F 逻辑）/ posted SMALLINT(0/1) / status（DRAFT/CALCULATED/POSTED/REVERSED）。
唯一：`uk_depr_asset_period(asset_id,period)` — 同资产同月只计提一次（幂等重算基础）。

### 3.5 A_DISPOSAL（处置单，单号 DSP-年-序）

asset_id（物理 FK A_ASSET）/ method（SCRAP/SELL/TRANSFER/DESTROY）/ appraisal JSONB（技术鉴定）/ residual_value NUMERIC(18,2) / approval_chain JSONB（审批留痕）/ related_voucher（F 逻辑）/ archive_ref（E-05/档案 逻辑）/ status（§4.8 处置状态机）。

### 3.6 关键关系（ER）

```
G_ORDER(到货验收 ACCEPTED) ──1:1── A_ASSET ──1:N── A_DEPRECIATION ──(分摊)── E_PROJECT / ──(凭证)── F(F-11)
        (A-03 from-receipt；source_ref=验收/合同)      A_ASSET ──1:N── A_DISPOSAL ──(残值)── F ; ──(归档)── E-05
A_CONSUMABLE(sku,batch) ──1:N── A_STOCK_TXN ──(领用归属)── E_PROJECT ; related_expense_id ── F_EXPENSE
A_ASSET ──(领用/调拨/归还流水)── A_STOCK_TXN(ref_asset_id)
```
- **A_ASSET 与 G_ORDER 到货 1:1**：一张验收合格到货单只生成一张资产卡；`from-receipt` 幂等，命中已建卡返回 `409`。
- **A_ASSET 与 A_DEPRECIATION 1:N**：一台资产每月一条折旧记录，`(asset_id,period)` 物理唯一；`A_ASSET.depr_accum/net_value` 为各期累计的派生汇总（单一事实来源在流水，台账字段冗余以支撑 <500ms 查询）。

## 4. 关键业务规则

### 4.1 资产全生命周期状态机（迁移表）

token：`PENDING_RECEIPT 待验收 / IN_USE 在用 / IDLE 闲置 / UNDER_MAINT 维修 / TRANSFERRING 调拨中 / PENDING_DISPOSE 待处置 / DISPOSED 已处置`

| 当前态 | 触发动作 | 目标态 | 守卫条件（前置校验） | 事件/留痕 |
|--------|----------|--------|----------------------|-----------|
| （无） | 建卡 / from-receipt | PENDING_RECEIPT | 要素缺失（value/custodian 任一为空）强制此态 | `asset.registered` |
| PENDING_RECEIPT | 要素补齐确认 | IN_USE | 价值、责任人、折旧要素完整；否则禁止进入折旧 | `asset.confirmed` |
| PENDING_RECEIPT | 直接确认在用 | IN_USE | 完整要素 + 权限（R-MANAGER） | `asset.confirmed` |
| IN_USE | 发起调拨 | TRANSFERRING | 涉密资产须保密审查通过（§4.6/联动 11） | `asset.transferring` |
| TRANSFERRING | 落地确认（使用法人登记领用） | IN_USE | 目标法人+部门+责任人就位 | `asset.transferred` |
| IN_USE | 报修 | UNDER_MAINT | 关联维保合同/工单（A-06） | `asset.maint` |
| UNDER_MAINT | 修复回归 | IN_USE | 停机时长计入使用率 | `asset.restored` |
| IN_USE | 长期未用/闲置标记 | IDLE | 使用率低于阈值（svc-policy） | `asset.idle` |
| IDLE | 复用/调剂 | IN_USE | — | `asset.in_use` |
| IN_USE/IDLE/UNDER_MAINT | 发起处置 | PENDING_DISPOSE | 无未完结调拨/维修 | `asset.dispose_applied` |
| PENDING_DISPOSE | 处置单完成（ARCHIVED） | DISPOSED | 处置链路 §4.8 走完、残值入账 | `asset.disposed` |
| DISPOSED | — | （终态） | 不可逆；档案封存可查 | — |

> 非法迁移（如 PENDING_DISPOSE→IN_USE、DISPOSED 复活）一律拒绝并写审计。`PENDING_RECEIPT` 态资产被折旧批处理排除（见 §4.3/§4.4）。

### 4.2 耗材/危化品领用状态机（含退库回环与效期分支）

token：`IN_STOCK 在库 / REQUESTED 领用申请 / DOUBLE_CONFIRM 双人确认 / ISSUED 已出库 / NEAR_EXPIRY 临期 / STAGNANT 呆滞 / EXPIRED 过期`

```
              ┌──────────── 退库 (RETURN_TO_STOCK) ───────────┐
              ▼                                                │
   IN_STOCK ──领用申请──▶ REQUESTED ──普通(单审批)──▶ ISSUED ──┘
                            │
                            └──危化品(is_hazard)──▶ DOUBLE_CONFIRM ──双签通过──▶ ISSUED
                                                    │
                                                    └──单锁/超额──▶ 硬拦截(403)+告警安全管理员
   效期/呆滞旁路（svc-policy 定时扫描 A_CONSUMABLE.status，非领用主链）：
   IN_STOCK ──临期(expire_date<=阈值)──▶ NEAR_EXPIRY ──长期未动──▶ STAGNANT ──过期──▶ EXPIRED
   EXPIRED 批次：冻结不可领用（stock-out 直接拒绝），只能走 HAZARD_DISPOSE/报废处置。
```

规则要点：
- **退库回环**：`ISSUED → IN_STOCK` 通过 `A_STOCK_TXN(type=RETURN_TO_STOCK)`，回写 `balance_after`。
- **普通 vs 危化分流**：`is_hazard=false` 走单审批直接 ISSUED；`is_hazard=true` 必须经 DOUBLE_CONFIRM 且 `double_confirm_by` 非空、与 `operator_id` 不同人，方可 ISSUED。
- **状态由规则引擎裁决**：临期/呆滞/低库存阈值来自 svc-policy（制度包），不硬编码。

### 4.3 A-03 到货转资产（要素缺失 → PENDING_RECEIPT，禁止进折旧）

- 入口：消费 `order.receipt_accepted`（G-17）或 `POST /asset/from-receipt`；与到货单 **1:1**，重复调用幂等（`Idempotency-Key` + 唯一约束），已建卡返回 409。
- 自动带出：`name/brand/model/value/source_ref(G_CONTRACT)/contractId`（复用 G-13 解析、A-15 AI 补全建议）。
- **要素缺失判定**：`value`、`custodian_id`、`depr_method/depr_years` 任一为空 → `status=PENDING_RECEIPT`，`missingFields` 记录缺项，返回前端标黄待补。
- **折旧准入闸门**：折旧批处理只选取 `status=IN_USE` 且要素完整（`value>0 AND custodian_id IS NOT NULL AND depr_method<>'NONE'`）的资产；PENDING_RECEIPT 永不进折旧，直到补齐确认转 IN_USE（§4.1）。

### 4.4 A-09 折旧计提 → A-12 成本分摊 → 凭证（F-11）

**按月计提（规则引擎，确定性）**：
1. `POST /asset/depreciation/run`，入参 `period`（YYYY-MM）、可选 `legalEntityId/policyPackId/assetIds`；缺省取命中 ACTIVE 制度包的 `policy_pack_id` 快照。
2. 选择范围：主责法人下 `status=IN_USE` 且要素完整的资产；逐台按 `depr_method` 计算本期 `depr_amount`：
   - `STRAIGHT_LINE`：`月折旧 = value × (1 - 残值率) / (depr_years × 12)`；残值率取自 policy_pack DSL。
   - `WORKLOAD`：`本期 = (value - 预计残值) × 本期工作量 / 预计总工作量`（工作量来源 A-13 机时/使用率）。
   - 末期满提，累计不超过 `value - 残值`。
3. 幂等：`(asset_id,period)` 唯一；重算=先 `REVERSED` 再写新记录，`policy_pack_id` 全程留快照以复算。
4. 回写 `A_ASSET.depr_accum / net_value`；发布 `asset.depreciation_posted` 事件。

**成本分摊（A-12，跨法人拆分避免重复计入）**：
- 依据 `alloc_project_ids = [{project_id, ratio, amount}]`，按各项目**使用比例**（机时/使用率/领用归属）拆分 `depr_amount`，`Σratio=1`、`Σamount=depr_amount`。
- **跨法人口径**：资产在**主责法人**计提，向跨法人项目分摊时按使用比例拆分，法人间不重复计入同一成本；每条分摊记录 `legal_entity_id`（计提法人）与 `project_id`（归属法人项目），对账以主责法人为准（§8）。

**凭证生成（→ F-11）**：
- 折旧完成后经 svc-integration-fin 生成凭证并回调 `POST /finance/voucher`，回写 `voucher_id`、`posted=1`、`status=POSTED`；凭证会计期间=period。

### 4.5 A-01 折旧政策/危化限额/安全库存（svc-policy 确定性规则）

| 规则域 | 来源 | 消费点 |
|--------|------|--------|
| 折旧方法/年限/残值率 | `sys_policy_pack.dsl_yaml` + `A_ASSET.depr_method/depr_years` | §4.4 计提、复算 |
| 危化限额（单人/单次/管制类） | policy_pack DSL `hazard_limit` | §4.6 stock-out 校验 |
| 安全库存水位 | `A_CONSUMABLE.safe_stock`（policy 可批量配置） | LOW_STOCK 判定、A-16 |
| 效期阈值 | policy_pack `near_expiry_days` | NEAR_EXPIRY/EXPIRED 扫描 |
| 呆滞阈值 | policy_pack `stagnant_days` + 领用流水 | STAGNANT 判定 |

svc-policy 每次裁决写 `sys_rule_hit`（rule_code + clause_ref + verdict PASS/REJECT/WARN + detail_json），保证可解释、可复算、可审计。

### 4.6 A-08 危化双人双锁（硬拦截 + 告警安全管理员）

- 触发：`A_CONSUMABLE.is_hazard=true` 的领用（stock-out）与出入库。
- **双人双锁**：出库必须两名不同授权人（`operator_id` + `double_confirm_by`），缺一不可；系统层面校验二人身份不同、均在库管员细分岗授权内。
- **超额/单锁硬拦截**：管制类（`hazard_level` 命中管制字典）单次/累计用量超 policy_pack `hazard_limit`，或双人缺一（单锁）——直接返回 **403**，不生成 ISSUED 流水，并触发 `asset.security_alert`（告警 SEC_ADMIN/安全管理员）。
- **MSDS 绑定**：入库须存在 `msds_url`；危化专区存放 `location` 校验。
- **危废处置**：空瓶/过期危化只能 `A_STOCK_TXN(type=HAZARD_DISPOSE)`，不可普通退库。

### 4.7 A-07/A-16 效期批次 / FIFO / 库存预警

- **批次与效期**：以 `(sku,batch_no)` 记库存；定时任务按 `expire_date` 与 policy 阈值刷新 `NEAR_EXPIRY/EXPIRED`。
- **过期冻结不可领用**：`status=EXPIRED` 批次 stock-out 一律拒绝，只能走 §4.6 危废 / §4.8 报废处置。
- **FIFO 领用**：stock-out 缺省自动选最早到期批次；**违反 FIFO 允许授权豁免但必须留痕**——请求带 `fifoExempt=true + fifoExemptApproverId`，落 `A_STOCK_TXN.fifo_exempt`，进审计与 `sys_rule_hit(WARN)`。
- **智能预警 A-16**：效期/安全库存=规则引擎（确定性）；呆滞、异常领用（如单人高频领用某危化）=异常检测模型（§4.11），输出预警+处置建议附解释。

### 4.8 A-10 处置（状态机 + 残值合理性校验）

token：`APPLIED 申请 → APPRAISED 鉴定 → APPROVED 审批 → EXECUTING 执行 → BOOKED 入账 → ARCHIVED 归档`

| 迁移 | 守卫 | 联动 |
|------|------|------|
| APPLIED→APPRAISED | 技术鉴定 `appraisal` 完整（结论+专家） | 涉密资产先过保密审查 |
| APPRAISED→APPROVED | 审批链 `approval_chain` 通过（R-LEADER/R-FINANCE） | 金额分级审批（policy） |
| APPROVED→EXECUTING | 执行处置（实物回收/变卖/销毁） | 资产置 PENDING_DISPOSE |
| EXECUTING→BOOKED | **残值合理性校验通过** + 残值入账凭证 | `related_voucher`→F |
| BOOKED→ARCHIVED | 档案封存 `archive_ref`→E-05 | 资产 DISPOSED |

- **残值合理性校验（A-10）**：`residual_value` 若 `> A_ASSET.value`（残值>原值）或 `< 0`（为负）→ **不自动 BOOKED，转财务复核**（`sys_rule_hit=REJECT/WARN`，写差异说明，财务确认后方可入账）。
- 处置完成发布 `asset.disposal_archived`，资产状态 PENDING_DISPOSE→DISPOSED。

### 4.9 A-11/A-14 账实一致三方对账与盘点

- **三方对齐**：财务账（F 资产原值/累计折旧）vs 资产卡（A_ASSET 台账）vs 实物（盘点采集 serial_no）。
- `POST /asset/inventory` 提交扫码/RFID 采集清单，`svc-asset` 比对生成差异表 `InventoryResult.differences`：`COUNT_GAIN 盘盈 / COUNT_LOSS 盘亏 / BOOK_MISMATCH 账卡不符`。
- **盘盈盘亏须原因 + 审批才调账**：差异记录 `reason` 必填、`needApproval=true`；审批通过后写 `A_STOCK_TXN(COUNT_GAIN/COUNT_LOSS)` 并同步调整台账与财务（不审批不调账）。全程进 `sys_audit_log`。

### 4.10 涉密资产与跨法人隔离（联动 11）

- `security_level>=SECRET` 资产：仅涉密网登记与查看，非涉密域查询接口（ledger/lifecycle/trace）**默认过滤其明细**，返回占位或无权（403/脱敏）。
- 涉密资产调拨/处置须 `secrecyReviewId`（保密审查单，联动 11）通过；涉密下行/上行经 `x_flow_audit` 留痕（EXF）。
- **跨法人**：主责法人建卡，使用法人登记领用（README 2.12）；折旧在主责法人计提，分摊到跨法人项目按使用比例拆分（§4.4）。

### 4.11 规则引擎 vs LLM 分工

| 能力 | 归属 | 说明 |
|------|------|------|
| 折旧计提、危化限额、安全库存、效期/呆滞阈值、残值校验 | **规则引擎（svc-policy）** | 确定性、可复算、可审计；结果落 `sys_rule_hit` |
| A-15 资产卡信息抽取（发票/合同→brand/model/serial_no/value…） | **LLM/OCR（svc-ai-gateway）** | 预填建议 + 每字段 `confidence`，<0.85 标黄；原值/序列号关键项人工确认，不直接落库 |
| A-16 异常领用检测（单人高频领用管制危化等） | **异常检测模型** | 输出预警+建议+解释；确定性阈值部分仍走规则引擎，模型只做偏离度识别 |
| A-17 重复购置识别 | **模型（相似度+存量/利用率）** | 采购前置提示"全院已有 N 台、均使用率 X%、建议共享/调剂"，附置信度 |

> 硬约束：金额、库存数量、审批流、状态迁移一律由规则引擎/事务决定，LLM 只做"建议/预警/抽取"，不得直接改账或绕过双人确认。AI 接口限流 20 req/min（429）。

## 7. 权限与隔离

- **租户/法人隔离**：所有查询强制 `tenant_id` + `legal_entity_id` 上下文；跨法人资产在主责法人建卡、使用法人登记领用，越权访问返回 403（README 2.12）。
- **密级隔离**：`security_level>=SECRET` 仅涉密网与授权人员可见明细，非涉密域过滤/脱敏；涉密登记、调拨、处置走保密审查 + `x_flow_audit`（EXF）留痕（联动 11，README 2.13）。
- **双人确认不可绕过**：危化 stock-out 服务端强制 `double_confirm_by != operator_id` 且二人在岗授权，前端置灰不能替代后端校验；缺失即拒绝，无旁路。
- **库管员细分岗**：库存收发、危化双锁由"资产管理员/库管员"细分岗授权（`sys_user_role` + `sys_admin_duty`），三员分立，禁止兼任。
- **角色权限矩阵**（对齐 PRD §9）：建卡 R-MANAGER（本法人）/价值字段 R-FINANCE；领用 R-STAFF（本人本项目）→R-MANAGER 审批；折旧/分摊 R-FINANCE 执行、R-AUDITOR 读+复算；处置发起 R-STAFF/组织鉴定 R-MANAGER/残值入账 R-FINANCE/审批 R-LEADER。
- **审计**：金额、状态、责任人、密级变更写 `sys_audit_log`（字段级 diff + 哈希链 sig），可复算、防篡改。

## 8. 异常与边界场景

| 场景 | 处理 |
|------|------|
| 验收即资产要素缺失（value/custodian 缺） | 建卡置 PENDING_RECEIPT + missingFields，禁止进折旧直到补齐（§4.3/4.4） |
| 账实不符（财务有卡无实物或反之） | 盘点差异生成盘盈/盘亏草案，须原因+审批才调账（§4.9） |
| 危化超领 / 单锁（双人缺一） | 硬拦截 403，不生成 ISSUED，触发 asset.security_alert 告警安全管理员（§4.6） |
| 折旧跨法人口径 | 主责法人计提、按使用比例拆分到跨法人项目，避免重复计入成本；对账以主责法人（§4.4） |
| 处置残值 > 原值 / 为负 | 校验拦截，转财务复核，确认后方可 BOOKED（§4.8） |
| 涉密资产外流 | 非涉密域不可见明细；调拨/处置须保密审查 + EXF 留痕；越权尝试审计告警（§4.10） |
| 效期与批次（过期/FIFO 违反） | 过期批次冻结不可领用走危废/报废；FIFO 违反允许授权豁免但 `fifo_exempt` 留痕（§4.7） |
| 折旧重复计提 | `(asset_id,period)` 物理唯一 + Idempotency-Key，重算先 REVERSED 再新写（§4.4） |
| 到货重复建卡 | G_ORDER 1:1 + `uk_asset_code`，重复 from-receipt 返回 409 |
| AI 误抽取 | 仅给建议不落库，confidence<0.85 标黄，原值/序列号强制人工确认（§4.11） |

## 9. 非功能需求（对齐 PRD §12）

- **性能**：资产台账查询 <500ms（`(tenant,legal_entity,status)` 组合索引 + 冗余净值/累计折旧免实时聚合）；月折旧批处理 5 万资产 <2min（分片并行 + 批量写 `A_DEPRECIATION`，`(asset,period)` 幂等可断点重跑）；扫码领用响应 <1s（serial_no/sku 索引 + 库存行级锁短事务）。
- **一致性**：账实一致三方（财务/资产卡/实物）可对齐；跨模块经 Kafka + Saga 最终一致，逻辑外键不回写对方库。
- **合规/可审计**：满足行政事业性国有资产与上级资产报表口径；折旧政策 `policy_pack_id` 快照可复算；处置、盘盈盘亏、豁免全留痕。
- **信创/等保三级**：PostgreSQL 15 方言 + 达梦差异注记（DDL 顶部 §2.4：IDENTITY/TIMESTAMP WITH TIME ZONE/JSONB→CLOB/BOOLEAN→SMALLINT/部分唯一索引降级复合唯一）；等保三级三员分立、字段级审计哈希链。
- **完整档案套打**：任一资产出"验收—责任链—折旧—分摊—处置"完整档案，套用 `sys_print_template`（ASSET_LABEL/资产卡模板）。
- **限流**：普通接口 100 req/min，AI 接口 20 req/min（429）。
