### 1.2 依赖模块

- **01 申报与立项（P）**：`E_PROJECT.application_id` 1:1 继承 `P_APPLICATION`；立项通过（P 状态 `EXECUTING`）后由 01 发事件 `application.approved` 触发本模块建执行态项目（Saga 起点，架构 §八）。

- **流程引擎（svc-workflow）**：变更逐级审批、中检发起、结题验收编排。
- **AI 中台（svc-ai-gateway）**：健康度归因、风险预警、报告起草。
- **common**：`sys_user/sys_org/sys_legal_entity/sys_dict/sys_policy_pack/e_trace_node/seq_prefix_registry(PRJ)`。

## 2. 服务与分层

本模块归属执行域微服务 **svc-project（执行域）**，与其他服务协作：

```
                        ┌────────────────────────────────────────┐
   网关/API Gateway ───▶ │  svc-project（执行域）                 │
   Bearer JWT/租户解析   │  ├─ Controller  /project/**            │
                        │  ├─ AppService  项目/任务/中检/变更/结题 │
                        │  ├─ Domain      状态机 + 健康度引擎      │
                        │  ├─ RuleEngine  风险确定性规则（本地）   │
                        │  └─ Repo        E_PROJECT / E_TASK ...   │
                        └───────┬───────────────┬─────────────────┘
                                │ Kafka 事件      │ 同步调用
        ┌───────────────────────┼───────────────┼───────────────────────┐
        ▼                       ▼               ▼                        ▼
 svc-policy（制度规则）   svc-workflow      svc-ai-gateway         svc-numbering
 中检模板/评分表/权限矩阵  变更/结题审批流   XGBoost+LLM+归因       申请 PRJ-年-序
 健康度权重(制度包快照)    Saga 编排         限流 20/min            统一编号中心
```

分层职责：
- **Controller**：参数校验、`Idempotency-Key` 去重、分页 `page/size`、租户与数据可见性拦截（见 §7）。
- **AppService**：用例编排（发起中检、变更影响分析、结题归档校验），跨服务调用与事务边界。
- **Domain**：`E_PROJECT` 生命周期状态机（§4.1）、健康度计算引擎（§4.2）；状态迁移集中校验，杜绝非法跳转。
- **RuleEngine**：本地确定性风险规则（§4.3），命中写 `sys_rule_hit`（可解释/可复算）。
- **Repo**：PostgreSQL 15；列表主路径命中 `(tenant_id, legal_entity_id, status)` 组合索引；`member_ids` GIN 表达式索引。
- **协作**：`svc-numbering` 分配 `code=PRJ-年-序`（Redis 号段 + `seq_allocation` 双写）；`svc-policy` 提供权重/阈值/中检模板并可快照 `policy_pack_id`；`svc-ai-gateway` 异步回调写 `ai_reason/ai_summary`；`svc-workflow` 承接变更与结题审批。

## 4. 关键业务规则

### 4.1 项目生命周期状态机迁移表

状态持久态为 README §4 token，中文仅映射。集中式迁移守卫（非法跳转返回 `409`）。

| # | 当前态 | 事件/动作 | 目标态 | 守卫条件 / 副作用 |
|---|--------|-----------|--------|-------------------|
| T1 | （立项） | application.approved（01） | `EXECUTING` | 签订合同/任务书签发后进入执行；分配 PRJ 编号 |
| T2 | `EXECUTING` | 到达中检节点/管理员发起 | `MID_CHECK` | 建 `E_MID_CHECK(PLANNED)`；发 `project.status.changed` |
| T3 | `MID_CHECK` | 结论=CONTINUE | `EXECUTING` | 关闭中检 `CONCLUDED` |
| T4 | `MID_CHECK` | 结论=CORRECT | `CORRECTING` | 写 `correct_deadline`；**冻结经费支出**（通知 03） |
| T5 | `MID_CHECK` | 结论=TERMINATE | `TERMINATED` | 触发经费清算流程（03 联动，§8） |
| T6 | `CORRECTING` | 整改完成/复核通过 | `EXECUTING` | 解冻支出；逾期仍 `status_overdue=1` 升级预警 |
| T7 | `EXECUTING` | 提交变更申请（审批中） | `CHANGING` | 建 `E_CHANGE_REQUEST(SUBMITTED)` |
| T8 | `CHANGING` | 变更生效（APPROVED 且无冲突） | `EXECUTING` | 回写预算/时间/成员；写历史快照；通知相关方 |
| T9 | `CHANGING` | 变更被拒/冲突回退 | `EXECUTING` | `status=ROLLED_BACK`；不做任何主数据变更 |
| T10 | `EXECUTING` | end_date 临近未完成 | `DELAYED` | 红黄高亮；触发延期建议 |
| T11 | `EXECUTING` | PI 提交结题申请（归档校验通过） | `COMPLETING` | 建 `E_FINAL_ACCEPT(APPLIED)`；缺项则拦截不回退态 |
| T12 | `COMPLETING` | 技术+财务双轨验收=PASS/PASS_WITH_CONDITIONS | `CLOSED` | 发 `project.completed` → 触发 03 决算 |
| T13 | `COMPLETING` | 结论=NEED_SUPPLEMENT（需补充材料） | `EXECUTING` | `E_FINAL_ACCEPT=NEED_SUPPLEMENT` |
| T14 | `COMPLETING` | 结论=FAIL | `EXECUTING` 或 `TERMINATED` | 视评审裁定；FAIL 且不可整改→终止 |
| T15 | *（除 CLOSED/TERMINATED 外任意态）* | PI 离职 | 冻结态守卫 | **禁止 T1/T7/T11**，触发交接重指定 PI（§8） |
| T16 | `CLOSED` | 归档 | `CLOSED`（终态） | 归档清单 `PASSED`，写 `e_trace_node` 终节点 |

> `CLOSED`、`TERMINATED` 为终态，不再向 `EXECUTING` 迁移。

### 4.2 E-10 健康度评分公式落库

**公式（权重可配，来自 `sys_policy_pack`，快照 `E_HEALTH_HISTORY.policy_pack_id` 供复算）**：默认权重 0.3 / 0.3 / 0.2 / 0.2。

```
health_score(0-100) = round( 100 × ( Wp·进度分 + Wb·经费分 + Wo·成果分 + Wr·风险分 ) )
  进度分 = Σ(已完成里程碑·weight) / Σ(应完成里程碑·weight)                 -- 0-1，来源 E_MILESTONE
  经费分 = 1 - min(1, abs(计划执行率 - 实际执行率) × 2)                     -- 0-1，来源 F 快照
  成果分 = 已产出成果数 / 任务书应产出指标数                                -- 0-1，来源 R（只读）
  风险分 = 1 - penalty/100, penalty = 变更次数×5 + 逾期任务数×3 + 未批支出笔数×10
```
> 四个分量归一化为 0-1 存 `E_HEALTH_HISTORY`（NUMERIC(6,4)），`total_score` 为 0-100（INT），避免 `NUMERIC(6,4)` 无法容纳 100 的溢出。PRD 原式 `风险分=100-penalty` 在落库时等价归一化。

**触发时机（双通道）**：
1. **每日 ETL 全量**：凌晨 ETL 后对全部 `status ∈ {EXECUTING,MID_CHECK,CHANGING,CORRECTING,DELAYED,COMPLETING}` 在研项目逐条写 `E_HEALTH_HISTORY(trigger_source=ETL)`，覆盖 100% 在研（NFR）。日切唯一键 `(project_id, snapshot_date)`，同日重算 upsert。
2. **事件实时刷新**：`project.change.effective`、`expense.approved`(F)、`output.registered`(R)、任务完成 触发 `E_HEALTH_HISTORY(trigger_source=EVENT)`，并回写 `E_PROJECT.health_score`。

**红黄绿阈值**（可配，默认）：`≥80 绿 / 60-79 黄 / <60 红`。列表、卡片墙、详情页、大屏一致渲染。

**AI 归因**：当 `total_score` 较上期下降（`status=DROPPED`），发 `project.health.dropped`，异步调 svc-ai-gateway 生成 `ai_reason`（"扣分主要来自经费执行率偏离 + 2 项任务逾期"），关键数字必须来自系统，不虚构。

### 4.3 E-11 风险预警（确定性规则 vs XGBoost/LLM 分工）

| 层 | 职责 | 触发 | 输出 |
|----|------|------|------|
| 确定性规则（RuleEngine，本地，可解释） | 强约束即时命中：经费执行率<30% 且临近截止、连续 3 次变更、逾期任务≥3、中检即将到期、连续 2 季度无进度 | 实时/ETL | 高优先级预警（HIGH/MED），命中写 `sys_rule_hit`，`rule_code` 可追溯 |
| XGBoost/LightGBM（svc-ai-gateway） | 基于历史项目特征预测延期/终止概率 | 每日批量打分 | 预测分值 + `risk_level` 升/降级，回流 `project.risk.detected` |
| LLM（svc-ai-gateway） | 自然语言风险提示语 + 建议动作（不决策，仅表达） | 预警生成时 | `suggestion` 文案；限流 20 req/min |

**闭环**：每条预警须被 PI/管理员 `ACK`（确认）或 `FALSE_POSITIVE`（误报），处置结果回流训练。目标：预警准确率 ≥70%、误报率 ≤20%。

### 4.4 变更影响分析与冲突回退（E-07）

流程：`变更申请 → 影响分析（自动） → 逐级审批（svc-workflow） → 生效/回退 → 通知 → 更新历史快照`。

**影响分析（提交即算，返回 `impact_analysis`）**：
- `BUDGET`：经费调整前后对比表（按科目）、对执行率与健康度经费分的影响预估。
- `DELAY`：`end_date` 顺延天数、受影响里程碑清单、是否需重新签订任务书（`resignTaskBook`）。
- `MEMBER`：成员增减、任务重分配提示。
- `TITLE/SCOPE`：任务书变更提示。

**冲突回退规则**（PRD 11）：当 `change_type=BUDGET` 且变更后预算 < 已实际支出（`spent_amount`）或低于已批复外拨/下限时，`conflict_flag=1`，**阻止生效并回退**（T9：`status=ROLLED_BACK`），主数据 `E_PROJECT`/预算不变更，返回 `409`，提示冲突科目。生效成功走 T8 并写 `snapshot_ref`。

### 4.5 E-15 归档清单缺项拦截结题

- 模板按 `project_type + stage` 配置（`E_ARCHIVE_CHECKLIST.project_id IS NULL`）。项目进入结题（T11）时按模板实例化项目侧清单（`project_id` 非空）。
- 逐项比对已上传 `E_PROJECT_DOC`（按 `category` 与 `mime_type` 校验），维护 `completed_count/required_count/completeness/blocked_items`。
- **拦截**：`completeness < 1`（存在 `required=true` 未上传项）→ 清单 `status=BLOCKED`，`POST /final-accept` 与 `archive-checklist/validate` 返回 `409`，项目不得由 `COMPLETING` 迁移到 `CLOSED`。缺项齐备后 `status=PASSED` 放行验收（T12）。

### 4.6 E-16 外协只引用不建表

外协/分包台账统一在 **09 G** 的 `G_OUTSOURCE`/`G_CONTRACT`（单号 `OSC-`、外协单位 `SOSC-`）。本模块仅：
- 以 `contract_id`/`outsource_unit_id` **逻辑引用**，在项目详情提供"外协视图"页签；
- 外拨经费联动由 `G/F` 事件驱动（架构 §八 Saga），本模块不重复存储可派生字段（README §5 + PRD 2.15 单一事实来源）。

{ ..., "eventType":"project.risk.detected",

## 8. 异常与边界

| 场景 | 处理 | 状态/事件 |
|------|------|-----------|
| **PI 离职**（sys_user.employment_status=RESIGNED） | 冻结项目变更与新增申请（守卫 T15），触发交接流程，管理员重指定 PI 后解冻 | `E_PROJECT` 保持原态但禁迁；发 `project.pi.changed` 通知；`member_ids`/`pi_user_id` 更新 |
| **项目长期不填报** | 连续 2 个季度无 `E_PROGRESS_REPORT` → 自动标黄，`risk_level` 升级 | `project.risk.detected`（RISK-NO-PROGRESS） |
| **中检逾期整改** | `correct_deadline` 过期未复核通过 → 项目留 `CORRECTING`，**经费支出冻结**（通知 03） | T4 保持；`E_MID_CHECK.status_overdue=1`；发 `project.status.changed` 升级预警 |
| **变更冲突** | 预算变更与实支出冲突 → `conflict_flag=1`，阻止生效并回退（§4.4） | T9 `ROLLED_BACK`；返回 409 |
| **结题成果不足** | 与任务书应产出指标比对（成果分母），不足项要求 PI 逐条说明理由方可提交验收 | `E_FINAL_ACCEPT=output_summary.insufficient` 需理由；缺理由 422 |
| **归档缺项** | 必交项未齐拦截结题（§4.5） | 清单 `BLOCKED`，409 |
| **终止项目** | `TERMINATED` → 触发经费清算流程（与 03 联动 Saga），生成清算任务，冻结剩余支出 | `project.terminated`；03 消费清算 |

## 9. 非功能

- **性能**：项目列表 1 万条 < 800ms（分页 + `(tenant_id, legal_entity_id, status)` 组合索引，避免全表 join，`member_ids` 用 GIN）；甘特图渲染 500 任务 < 1s（`GET /tasks?view=GANTT` 一次返回扁平树 + 依赖，前端虚拟滚动，接口 P95 < 500ms）。
- **健康度覆盖**：100% 在研项目每日 ETL 快照（T 态全覆盖），可回溯任意日期状态（`E_HEALTH_HISTORY` 日切 + 事件）。
- **质量目标**：中检按时完成率 ≥95%；预警准确率 ≥70%、误报率 ≤20%。
- **可用性**：移动端 PI 可查概览、更新任务、审批简单变更；AI 接口限流 20 req/min。
- **可追溯/可复算**：`health_score`、变更、结题决策均落 `e_trace_node` + `sys_rule_hit` + `policy_pack_id` 快照。
- **信创**：DDL 与索引按 README §2.4 达梦差异替换（JSONB→CLOB、部分唯一索引→普通唯一索引+deleted 复合键）。
