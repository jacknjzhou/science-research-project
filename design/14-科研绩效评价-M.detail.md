> 契约见 design/14-科研绩效评价-M.openapi.yaml；建表见 design/14-科研绩效评价-M.ddl.sql；术语/编号以 PRD/README 为准，业务依据规格 §4。

## 4.1 数据字典

模块 M（科研绩效评价）由 5 张业务表构成：**m_scheme**（绩效方案/考核规则容器）、**m_scheme_factor**（考核因子与计分规则）、**m_record**（人员×方案×周期的绩效记录，自动计分产出）、**m_record_item**（因子明细得分与证据）、**m_payout**（从 APPROVED 记录发起的在线审批发放）。方言 PostgreSQL 15；数值精度约定：权重 `NUMERIC(6,2)`、计分原始度量 `metric_value NUMERIC(18,4)`、分值 `score NUMERIC(10,2)`、金额 `NUMERIC(18,2)`；时间 `TIMESTAMPTZ`；枚举一律 `VARCHAR + CHECK`；字典项走 `sys_dict`。

**跨模块引用均为逻辑外键（只存 `*_id`，不建物理 FK）**：`staff_user_id / payee_user_id / creator_id → sys_user`、`dept_id / scope_dept_id → sys_org`、`scope_staff_type / pay_channel → sys_dict`、`voucher_code → F 凭证`、`policy_pack_id → sys_policy_pack`、`data_source=R_OUTPUT/F_INCOME/E_PROJECT/T_DEAL` 指向各来源真表。**同模块内建物理外键**：`m_scheme_factor.scheme_id → m_scheme(id)`（factor→scheme）、`m_record.scheme_id → m_scheme(id)`（record→scheme）、`m_record_item.record_id → m_record(id)`（item→record）、`m_payout.record_id → m_record(id)`（payout→record）。编号：`m_scheme.code / m_record.code` 前缀 `PERF`、`m_payout.code` 前缀 `PAY`（由 svc-numbering 分配，见 00-common `seq_prefix_registry`）。

### m_scheme（绩效方案）

主键 `id BIGINT GENERATED ALWAYS AS IDENTITY`；通用审计列 `code / tenant_id / status / deleted / creator_id / modifier_id / created_at / updated_at / remark`；治理列 `security_level / legal_entity_id / policy_pack_id`。

| 列 | 类型 | 说明 |
|----|------|------|
| `status` | VARCHAR(32) NOT NULL DEFAULT 'DRAFT' | 方案状态，CHECK `DRAFT/ACTIVE/SUPERSEDED` |
| `name` | VARCHAR(128) NOT NULL | 方案名称 |
| `period_type` | VARCHAR(16) NOT NULL | 周期类型，CHECK `YEAR/QUARTER/MONTH` |
| `scope_dept_id` | BIGINT | 考核范围部门，逻辑外键 → `sys_org(id)`；**空=全院** |
| `scope_staff_type` | VARCHAR(32) | 考核人员类型，逻辑引用 `sys_dict(staff_type)`；**空=全部** |
| `effective_period` | VARCHAR(32) NOT NULL | 生效周期串，如 `2026` / `2026Q1` / `2026-03`；决定 calculate 时间窗 |
| `version` | INT NOT NULL DEFAULT 1 | 方案版本号 |
| `active` | BOOLEAN NOT NULL DEFAULT FALSE | 当前生效标记，与 `status=ACTIVE` 同步维护；同维度仅一个 true |

索引/唯一：
- **表达式部分唯一** `uk_m_scheme_active (tenant_id, period_type, effective_period, COALESCE(scope_dept_id,0), COALESCE(scope_staff_type,'')) WHERE active = TRUE AND deleted = 0`——同租户+周期类型+生效期+范围维度只允许一个生效方案（用 `COALESCE` 把可空的 dept/staff_type 归一为 `0`/`''` 参与唯一键）。
- `uk_m_scheme_code (tenant_id, code) WHERE deleted = 0`、`idx_m_scheme_tenant_st (tenant_id, status)`。

### m_scheme_factor（考核因子 / 计分规则）

| 列 | 类型 | 说明 |
|----|------|------|
| `id` | BIGINT IDENTITY PK | 主键 |
| `scheme_id` | BIGINT NOT NULL | **物理外键** → `m_scheme(id)` |
| `factor_code` | VARCHAR(64) NOT NULL | 因子编码 `PAPER/PATENT/PROJECT/INCOME/AWARD/TRANSFER/BOOK/SOFTWARE/…`（走 `sys_dict`） |
| `factor_name` | VARCHAR(128) | 因子名称 |
| `weight` | NUMERIC(6,2) NOT NULL DEFAULT 0 | 权重占比 |
| `scoring_rule` | JSONB NOT NULL DEFAULT '{}' | **计分规则 JSON**，见下（四 `method` 语义） |
| `max_score` | NUMERIC(10,2) | 该因子封顶分 |
| `data_source` | VARCHAR(32) NOT NULL | 取数来源，CHECK `R_OUTPUT/F_INCOME/E_PROJECT/T_DEAL/MANUAL` |
| `clause_ref` | VARCHAR(256) | 制度出处（可解释性留痕） |
| `sort_no` | INT NOT NULL DEFAULT 0 | 排序号 |

唯一 `uk_m_factor (scheme_id, factor_code)`（同方案内因子编码唯一）。索引 `idx_m_factor_scheme (scheme_id)`。

**`scoring_rule` JSON 的四种 `method` 语义**（calculate 引擎据此把 `metric_value` 折算为 `raw_score`）：

| `method` | 语义 | 参数 | 计算 |
|----------|------|------|------|
| `COUNT` | 单据数 × 单价 | `unit` | `raw = 单据条数 × unit` |
| `BY_LEVEL` | 按成果/项目等级取分值 | `levelMap: {output_type → 分值}` | `raw = Σ levelMap[每条单据的 output_type]` |
| `BY_AMOUNT` | 金额 × 系数 | `unit` | `raw = metric(金额) × unit` |
| `LADDER` | 阶梯区间映射分值 | `ladder: [{min,max,score}]`，区间 `[min,max)` | 命中 `metric_value ∈ [min,max)` 的那档取 `score` |

形态示例：`{"method":"BY_LEVEL","levelMap":{"SCI":30,"核心":15}}`、`{"method":"LADDER","ladder":[{"min":0,"max":10,"score":5},{"min":10,"max":null,"score":12}]}`。

### m_record（绩效记录：某人×某方案×某周期）

主键 `id`；通用审计列 + `security_level / legal_entity_id`。

| 列 | 类型 | 说明 |
|----|------|------|
| `scheme_id` | BIGINT NOT NULL | **物理外键** → `m_scheme(id)` |
| `staff_user_id` | BIGINT NOT NULL | 被考核人，逻辑外键 → `sys_user(id)` |
| `period` | VARCHAR(32) NOT NULL | 记录所属周期（继承方案 `effective_period`） |
| `dept_id` | BIGINT | 归属部门，逻辑外键 → `sys_org(id)` |
| `total_score` | NUMERIC(10,2) NOT NULL DEFAULT 0 | 加权总分 |
| `rank` | INT | 名次（排行计算回填） |
| `calc_detail` | JSONB NOT NULL DEFAULT '{}' | 计分明细快照 / 算法参数留痕 |
| `calc_batch` | VARCHAR(64) | 计算批次号，同 batch 重算幂等（upsert 覆盖） |
| `calc_at` | TIMESTAMPTZ | 计分时间 |
| `confirmed_by / confirmed_at` | BIGINT / TIMESTAMPTZ | 确认人 / 确认时间 |
| `approve_by / approve_at` | BIGINT / TIMESTAMPTZ | 审批人 / 审批时间 |
| `appeal_reason` | VARCHAR(512) | 申诉理由（APPEAL 时填） |
| `void_reason` | VARCHAR(512) | 作废理由（VOID 时填） |
| `status` | VARCHAR(32) NOT NULL DEFAULT 'CALCULATED' | 状态机 token，CHECK `CALCULATED/CONFIRMED/APPROVED/PAID/APPEAL/VOID`（见 §4.2） |

索引/唯一：
- **部分唯一（幂等 upsert）** `uk_m_record (scheme_id, staff_user_id, period) WHERE deleted = 0`——同一「方案×人员×周期」只有一条活跃记录，`calculate` 重复触发按此键 upsert 覆盖，保证重算幂等。
- `uk_m_record_code (tenant_id, code) WHERE deleted = 0`；`idx_m_record_scheme_period (scheme_id, period)`、`idx_m_record_staff (staff_user_id, period)`、`idx_m_record_dept (dept_id)`。

### m_record_item（因子明细得分）

| 列 | 类型 | 说明 |
|----|------|------|
| `id` | BIGINT IDENTITY PK | 主键 |
| `record_id` | BIGINT NOT NULL | **物理外键** → `m_record(id)` |
| `factor_code` | VARCHAR(64) NOT NULL | 对应因子编码 |
| `metric_value` | NUMERIC(18,4) NOT NULL DEFAULT 0 | 原始度量：篇数 / 金额 / 项数 |
| `raw_score` | NUMERIC(10,2) NOT NULL DEFAULT 0 | 规则映射后未加权分 |
| `weighted_score` | NUMERIC(10,2) NOT NULL DEFAULT 0 | `raw × weight`（或按权重占比） |
| `evidence` | JSONB NOT NULL DEFAULT '[]' | 命中单据 `[{objectType,objectId,code,value}]`，可反查来源真表 |
| `tenant_id` | BIGINT NOT NULL | 多租户 |

唯一 `uk_m_item (record_id, factor_code)`（一次记录内每因子一行明细，随 calculate 整体覆盖）。索引 `idx_m_item_record (record_id)`。

### m_payout（绩效发放在线审批）

主键 `id`；通用审计列 + `security_level / legal_entity_id`。

| 列 | 类型 | 说明 |
|----|------|------|
| `record_id` | BIGINT NOT NULL | **物理外键** → `m_record(id)`（从 APPROVED 记录发起） |
| `payee_user_id` | BIGINT NOT NULL | 收款人，逻辑外键 → `sys_user(id)` |
| `amount` | NUMERIC(18,2) NOT NULL | 发放金额（元） |
| `period` | VARCHAR(32) | 发放周期 |
| `pay_channel` | VARCHAR(32) | 工资 / 专项，逻辑引用 `sys_dict` |
| `approver_ids` | JSONB NOT NULL DEFAULT '[]' | 审批链快照 `[{userId,at,action}]` |
| `approved_at / paid_at` | TIMESTAMPTZ | 审批 / 付款完成时间 |
| `voucher_code` | VARCHAR(64) | 联动 F 凭证号，逻辑外键 |
| `reject_reason` | VARCHAR(512) | 驳回理由 |
| `status` | VARCHAR(32) NOT NULL DEFAULT 'DRAFT' | 状态机 token，CHECK `DRAFT/APPROVING/APPROVED/PAID/REJECTED`（见 §4.2） |

索引/唯一：
- **部分唯一（一记录一有效发放）** `uk_m_payout_record (record_id) WHERE deleted = 0 AND status <> 'REJECTED'`——一条绩效记录最多挂一笔未驳回的发放；被 `REJECTED` 后允许重新发起（旧单被唯一键排除）。
- `uk_m_payout_code (tenant_id, code) WHERE deleted = 0`；`idx_m_payout_tenant_st (tenant_id, status)`。

**达梦（信创）注意**：`uk_m_scheme_active` 用了表达式唯一索引（`COALESCE(scope_dept_id,0)` / `COALESCE(scope_staff_type,'')`）；PG 基线保留，若达梦方言不支持表达式唯一索引，则生产改由应用层校验「同维度仅一个 active」的唯一性。

## 4.2 状态机（端点驱动、硬编码，非通用引擎）

状态迁移由具体端点触发，不引入通用工作流引擎。合法性由 handler 依据当前 `status` 硬编码校验。

### 记录状态机 `m_record.status`（源自规格 §4.2）

```
CALCULATED ──confirm(本人/管理员)──▶ CONFIRMED ──approve──▶ APPROVED ──payout完成(PAID)──▶ PAID
     │                                    │
     ├──────────── appeal ────────────────┴──▶ APPEAL ──重算(calculate)──▶ CALCULATED
     └───────────────── void ─────────────────────────────────────────▶ VOID（终态）
```

### 发放状态机 `m_payout.status`（源自规格 §4.2）

```
DRAFT ──submit──▶ APPROVING ──approve──▶ APPROVED ──pay──▶ PAID（终态）
                    │
                    └──reject──▶ REJECTED（回退，可重新发起新单）
```

端点 → 迁移映射（tag: performance）：

| 端点 | 迁移 |
|------|------|
| `POST /perf/records/{id}/confirm` | `CALCULATED` → `CONFIRMED` |
| `POST /perf/records/{id}/appeal` | `CALCULATED` / `CONFIRMED` → `APPEAL` |
| `POST /perf/records/{id}/approve` | `CONFIRMED` → `APPROVED` |
| `POST /perf/records/{id}/void` | 非终态 → `VOID` |
| `POST /perf/payouts`（发起） | 新 `m_payout` = `DRAFT`（要求记录已 `APPROVED`） |
| `POST /perf/payouts/{id}/approve` | `DRAFT`/`APPROVING` → `APPROVING`/`APPROVED` |
| `POST /perf/payouts/{id}/pay` | `APPROVED` → `PAID`（同步记录 → `PAID`） |
| `POST /perf/payouts/{id}/reject` | `APPROVING` → `REJECTED` |

规则（硬编码校验）：

- 不在合法迁移集合内的状态变更一律拒绝，返回业务码 **`40901`**（非法状态迁移）。
- 无权限发起某动作（如 R-STAFF 调 `approve`、或读他人 `/perf/me` 之外记录），返回 **`40301`**（越权）。
- `APPEAL` 后由管理员重新触发 `calculate`，命中 `uk_m_record` upsert 覆盖回 `CALCULATED`（重算幂等）。
- `VOID` / `PAID` 为记录终态；发放 `REJECTED` 后记录不受影响，可再次发起新发放单。
- 发放与记录联动：`m_payout` 到达 `PAID` 时把对应 `m_record.status` 推进到 `PAID`。

## 4.3 权限矩阵（Casbin RBAC + handler ABAC）

行=端点类别，列=角色；`✓` 允许、`只读` 仅查看、`—` 不允许、`限本人` 由 handler ABAC 再收敛。依据规格 §4.4。

| 端点类别 | R-STAFF | R-MANAGER | R-LEADER | R-AUDITOR | R-ADMIN |
|----------|:-------:|:---------:|:--------:|:---------:|:-------:|
| 方案配置 `POST/PUT/DELETE /perf/schemes*`、`activate` | — | ✓ | ✓ | — | ✓ |
| 因子配置 `POST/PUT/DELETE /perf/schemes/{id}/factors*` | — | ✓ | ✓ | — | ✓ |
| 触发计算 `POST /perf/schemes/{id}/calculate` | — | ✓ | ✓ | — | ✓ |
| 记录列表/详情 `GET /perf/records`、`/perf/records/{id}[/detail]` | —（非本人 40301） | ✓ | ✓ | 只读 | ✓ |
| 确认 `POST /perf/records/{id}/confirm` | 限本人 | ✓ | ✓ | — | ✓ |
| 申诉 `POST /perf/records/{id}/appeal` | 限本人 | ✓ | ✓ | — | ✓ |
| 记录审批 `POST /perf/records/{id}/approve` | — | ✓ | ✓ | — | ✓ |
| 作废 `POST /perf/records/{id}/void` | — | ✓ | ✓ | — | ✓ |
| 发放发起/审批/付款/驳回 `POST /perf/payouts*` | — | ✓ | ✓ | — | ✓ |
| 我的绩效 `GET /perf/me?period=` | ✓（**ABAC 限本人**） | ✓ | ✓ | ✓ | ✓ |
| 排行/分布 `GET /perf/ranking` | — | ✓ | ✓ | 只读 | ✓ |

要点：

- **`/perf/me` ABAC 限本人**：任何角色命中该端点时，handler 强制把查询谓词锁定为 `staff_user_id == auth.DomainFrom(c).UserID`（当前登录用户），只回本人记录，不接受越权指定他人。
- **confirm/appeal 本人**：`R-STAFF` 只能对 `staff_user_id` 归属本人的记录发起确认/申诉；命中他人记录返回 `40301`。
- **配置/计算/审批/发放**：`R-MANAGER`、`R-LEADER` 主责，`R-ADMIN` 由 `/api/v1/*` 通配兜底。
- **R-AUDITOR 只读**：仅 `GET`（records / ranking / me），不可发起任何状态迁移动作。
- 分层落地：**Casbin `policy.csv` 是传输层粗放行**（`/api/v1/perf/* GET`、`/api/v1/perf/schemes* POST/PUT/DELETE`、`/api/v1/perf/*/calculate POST`、`/api/v1/perf/records/*/confirm|appeal|approve|void POST`、`/api/v1/perf/payouts* ...`）；**逐行 ABAC（`tenant_id`、`staff_user_id==UserID`）在 handler 内强制**；`BuildCaps` 将 p 规则派生为前端 `caps` 由 `/auth/me` 回显。
