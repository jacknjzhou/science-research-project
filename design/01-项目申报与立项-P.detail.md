## 2. 服务与分层

微服务 `svc-project` 内部按 DDD 分层，P 域为其一个上下文边界：

```
Controller  ← REST 入站（01-...openapi.yaml），做参数校验、幂等头处理、DTO↔Domain 转换
Service     ← 应用服务（编排事务、状态机迁移、调用平台服务）
Domain      ← 聚合根：Application（含 Section/BudgetLine 子实体）、ReviewTask、ReviewResult、TaskBook
Repository  ← 持久层（MyBatis/JPA），落 P_* 表；跨模块只存对方 id
领域事件     ← 出站 Kafka（domain.action），见 §5
```

**用到的平台服务（跨服务调用，均为同步 RPC 或事件）**：

| 平台服务 | 用途 | 时机 |
|----------|------|------|
| `svc-numbering` | 分配 `P_APPLICATION.code`、`P_TASK_BOOK.code`（复用前缀 PRJ）、指南/模板配置码 | 创建申报 / 生成任务书（幂等取号） |
| `svc-policy` | 确定性判定：形式审查、预算限额/科目比例、审批权限矩阵、回避关系硬约束 | 提交/打分/决议前，落 `sys_rule_hit` 记 rule_code+出处 |
| `svc-workflow` | 多级审批与推荐链（P-06）、公示异议独立状态机（P-11） | SUBMITTED→FORMAL_CHECK→RECOMMENDED、决议公示 |
| `svc-ai-gateway` | LLM 起草/合规/查重/评审意见（P-13/14/15/16），RAG 检索 + 置信度 | 编辑页触发、预算失焦、评审辅助 |

**只读引用的共享实体（跨模块逻辑外键，不建物理外键，见 `README.md §5`）**：
`pi_user_id`/`expert_user_id`/`decided_by`/`creator_id` → `sys_user`；`department_id` → `sys_org`；`subject_code` → 03 `F_SUBJECT`；`print_template_code` → `sys_print_template`；`project_id` → 02 `E_PROJECT`。

## 4. 关键业务规则

### 4.1 申报状态机迁移表（权威 token 见 `README.md §4`）

| 当前 | 迁移 | 触发条件 | 目标 | 事件 |
|------|------|----------|------|------|
| DRAFT | submit | 形式审查通过 + PI 在职 + 未超期 | SUBMITTED | application.submitted |
| DRAFT | withdraw | PI 主动申请且未进入评审 | WITHDRAWN | — |
| SUBMITTED | formal_pass | svc-policy 校验项全 PASS | FORMAL_CHECK | — |
| SUBMITTED/FORMAL_CHECK | 退回 | 形式审查不通过（40904） | DRAFT | — |
| FORMAL_CHECK | recommend | 部门→院所→主管推荐（svc-workflow） | RECOMMENDED | application.recommended |
| RECOMMENDED | dispatch | 分派评审专家（P-08） | UNDER_REVIEW | — |
| UNDER_REVIEW | need_interview | 项目类型需会评 | INTERVIEWING | — |
| INTERVIEWING | collect | 全部必需轮次提交（P-09/10） | DECIDED | review.completed |
| UNDER_REVIEW | collect | 无需会评直接汇总 | DECIDED | review.completed |
| DECIDED | approve_publicize | decision=APPROVED 且进入公示 | PUBLISHED | — |
| DECIDED | reject | decision=REJECTED | REJECTED | — |
| PUBLISHED | sign | 任务书全部签章完成 | SIGNED | — |
| SIGNED | enter_exec | project.approved 落地/02 建项 | EXECUTING | project.approved |
| SUBMITTED..UNDER_REVIEW | terminate | 进入评审后不可撤回，终止理由必填 | REJECTED | — |

- **WITHDRAWN 触发**：仅 `DRAFT/SUBMITTED/FORMAL_CHECK`（未进入 UNDER_REVIEW）由 PI 主动申请。
- **REJECTED 触发**：决议 decision=REJECTED，或进入评审后 terminate（终止）。终态不可逆。

### 4.2 形式审查校验项（P-05，svc-policy 确定性判定，落 sys_rule_hit）

| 校验项 | 规则 | 未过处理 |
|--------|------|----------|
| 章节完整性 | template.sections 中 required=true 全部非空 | 阻断提交（40904） |
| 字数限制 | 各 section.word_count ≤ sections[].maxWords | 阻断 |
| 图表数量 | table_count 在上限内 | 告警 |
| 附件齐全 | 必传附件类型齐全、单文件≤100MB 格式白名单 | 阻断 |
| 签字/承诺 | 科研诚信承诺已签署 | 阻断 |
| 预算合规 | 各科目比例/限额（间接费用≤20% 等，svc-policy） | 阻断（确定性，非 LLM） |
| PI 在职 | pi_user_id → sys_user.employment_status='ONBOARD' | 阻断（40903） |
| 时效 | now() ≤ guideline.apply_end_at | 阻断（40902 超期） |

### 4.3 专家回避规则（P-07/08，确定性硬约束）

分派候选专家时，命中下列任一即 `conflict_flag=TRUE` 并**自动排除**（svc-policy 判定，非 LLM）：与 PI 同单位（department_id 相同）；近 3 年有合作关系（查 07 S 合作图谱）；存在师生关系。分派同时按方向匹配度 + 当前负荷（active task 数）均衡。

### 4.4 重复申报查重（P-17）

- **硬约束**：同指南同 PI 仅一份有效申报 → 唯一部分索引 `uk_p_application_once` 拦截（40901）。
- **软预警**：题名相似度 > 0.9 弹提示；`/apply/ai/duplicate-check`（LLM+向量）输出跨团队/跨人重复选题冲突清单与合并建议，**仅作管理员参考，不作强制驳回**（PRD 8.3）。

### 4.5 超期拦截（§11）

`now() > guideline.apply_end_at` 一律拒绝 submit（40902）；截止前 3 天 / 1 天多次推送提醒（通知中心，站内+微信+短信）。

### 4.6 规则引擎（svc-policy）与 LLM（svc-ai-gateway）分工（对齐 PRD 2.10）

| 判定 | 归属 | 产物 |
|------|------|------|
| 形式审查、预算限额/科目比例、审批权限矩阵、回避关系、超期/在职 | **svc-policy 规则引擎** | 命中 rule_code + 出处条款 + PASS/REJECT/WARN，可复算，落 `sys_rule_hit` |
| 申报书起草（P-13）、预算风险提示文案（P-14）、查重相似度（P-15）、评审意见草稿（P-16） | **LLM** | 附置信度与理由，低置信回落人工；不得改写已提交数据、不作唯一决策依据 |

AI 起草内容强制打"AI 生成"水印、PI 显式确认；置信度 <0.7 降级为要点建议；LLM 不可用时按钮置灰（50301）不阻塞业务。

## 5. 事件契约（Kafka，`domain.action`）

统一信封（`README.md §3.1`）：`{ eventId, eventType, occurredAt, tenantId, legalEntityId, traceId, payload }`。P 表不落 `legal_entity_id`，事件里的 `legalEntityId` 由 `pi_user_id → sys_user.legal_entity_id` 在发布时解析填充。

**application.submitted**
```json
{ "eventId":"uuid","eventType":"application.submitted","occurredAt":"2026-10-13T08:00:00Z",
```

## 7. 权限与隔离（RBAC + ABAC，引用角色代号 R-*）

- **RBAC**：起草/编辑/提交/撤回仅 `R-STAFF` 对**自己的**申报（ABAC 属性 `pi_user_id == subject.userId`）；推荐上报/分配评审/公示 `R-MANAGER`；决议 `R-LEADER`；评审打分 `R-EXPERT`（仅被分派任务）；模板配置 `R-ADMIN`；`R-AUDITOR` 全程只读可导出。对齐 PRD §9 权限矩阵。
- **ABAC 关键属性**：租户 `tenant_id`（跨租户一律拒绝）、`pi_user_id`、`application_id`、时段（公示期）、评审轮次。
- **评审期匿名化**：`P_REVIEW_TASK.anonymous_view=TRUE` 时接口对 R-EXPERT 隐藏 PI 姓名与 `department_id`（视图脱敏，会评阶段视项目类型决定是否实名）。
- **决议前评分不可见**：`P_REVIEW_RESULT.final_score/rank` 与 `score_detail` 在 `decision` 未定档（DECIDED 之前）对 R-STAFF 不可见；PI 之间未立项申报严格互不可见。
- **PI 不在职拦截**：提交前校验 `sys_user.employment_status='ONBOARD'`，否则 40903。
- **审计**：所有 CUD/下载/查看写 `sys_audit_log`（字段级 diff + 数字签名）。

| 场景 | 处理 | 码 |

| 评分并列 | 触发复议流程 | review.completed.tieFlag |

## 9. 非功能与性能

| 指标 | 目标 | 落地手段（索引/缓存/架构） |
|------|------|---------------------------|
| 单份申报书保存 | <300ms | P_APPLICATION_DOC 按 (application_id,section_code) upsert 部分唯一索引，乐观锁 doc_version；写走主库、读走缓存 |
| 指南列表加载 | <500ms（1 万条内） | `idx_p_guideline_tenant_st`/`idx_p_guideline_type`/`idx_p_guideline_end` 覆盖筛选；分页 size≤200；Redis 缓存热点指南列表 + ES 承接关键词/全文检索（达梦用 ES 替代 tsvector） |
| AI 起草首字节 | <2s，完整 <15s | svc-ai-gateway 流式 SSE 返回；RAG 向量库（pgvector/Milvus）+ 权限过滤 Top-5；20 req/min 限流 |
| 并发评审 | 500 人在线无卡顿 | `idx_p_review_expert(expert_user_id,status)` 快速取任务队列；打分 upsert 无全局锁；评审结果 Redis 缓存；决议前评分可见性走服务端判定 |
| 配置生效 | 模板 ≤5min | 模板缓存版本号失效广播；active 部分唯一索引保证单版本 |
| 可用性 | 表单键盘流、Word 粘贴保格式、移动端指南浏览+进度查询 | 前端 + 只读 REST 复用 |
| 安全 | 未立项互不可见、决议前评分不可见、全量留痕 | §7 ABAC + sys_audit_log |

**缓存策略**：指南/模板（读多写少，Redis TTL + 变更失效）；评审任务队列（按 expert+status 短 TTL）；申报草稿（写穿透，避免脏读）。编号取号走 svc-numbering Redis 号段 + `seq_allocation` 双写。

## 10. 待细化问题

1. **单号前缀**：P_APPLICATION / P_TASK_BOOK 现复用已登记前缀 `PRJ`（项目/立项，P/E 拥有）。指南、模板的 `code` 目前作配置码而非全局单号；若需正式单号，须先在 `../PRD/README.md §2.11` 与 `seq_prefix_registry` 登记新前缀（如 GL/TP），不得自造。

5. **协同编辑并发**：多人批注/实时协同（CRDT/OT）与 30s 自动存的版本合并策略待前端方案确认。
6. **评审负荷算法**：AI 智能分派的匹配度/负荷权重与可解释性输出格式，待与 svc-policy/svc-ai-gateway 对齐阈值。
7. **P-18 横向立项**：经费来源与成果归属确认字段、移交 G-10 横向委托合同的 Saga 细节待与 09 模块联调。
