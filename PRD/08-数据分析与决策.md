# 08 · 数据分析与决策支持 PRD

**模块代号**：D（Data & Decisions）  
**优先级**：M2-M3  
**依赖模块**：所有业务模块 · 数据仓库 · BI 引擎 · AI 中台

---

## 1. 模块概述与目标

将分散在各业务模块的数据资产化：构建**数据仓库 + 指标体系 + 画像引擎 + 大屏与报表 + AI 洞察**五层能力，服务三类用户——领导决策、管理运营、上报合规。

**目标**：核心报表一键生成率 100%；数据新鲜度 T+1；院所领导日均访问率 ≥ 60%。

## 5. 数据模型

### 5.1 数据仓库分层

采用经典 **ODS → DWD → DWS → ADS** 四层：

**ODS**（贴源层）：与业务库结构 1:1，日增量抽取。

**DWD**（明细层）：清洗后的事实表 + 维度表。核心事实：`dwd_project_apply`, `dwd_expense`, `dwd_output`, `dwd_transfer_deal`。核心维度：`dim_staff`, `dim_department`, `dim_project_type`, `dim_subject`, `dim_time`。

**DWS**（汇总层）：轻度聚合主题宽表。如：`dws_staff_yearly`, `dws_project_yearly`, `dws_dept_monthly`。

**ADS**（应用层）：面向具体报表与大屏的结果表。

### 5.2 主要应用层表

**D_METRIC**（指标字典）  
`id, code, name, category, unit, formula_sql, drill_dims(JSON), refresh_freq, owner_role`

示例指标：在研项目数、年度经费到账额、经费执行率、篇均被引、Nature/Science 系列数、转化收益、PI 平均经费、中检通过率……

**D_REPORT**（报表定义）  
`id, code, name, type(DASHBOARD/TABLE/CHART), schema_json, data_source, permission_scope, schedule`

**D_REPORT_INSTANCE**（报表实例，含快照）  
`id, report_id, params(JSON), snapshot_url, generated_at, generated_by, expires_at`

**D_SCREEN**（大屏配置）  
`id, name, layout_json, widgets(JSON [{type, data_metric_id, viz_config}]), rotation_seconds`

**D_SUBSCRIPTION**（订阅）  
`id, user_id, report_id, frequency(DAILY/WEEKLY/MONTHLY), channel(EMAIL/WECHAT), last_sent_at`

**D_QUERY_LOG**（自然语言查询日志）  
`id, user_id, question_text, generated_sql, executed_at, row_count, feedback`

**D_BENCHMARK**（机构对标）  
`id, peer_institute_id, year, metric_code, peer_value, our_value, rank`

**D_FORECAST**（预测快照）  
`id, target_metric, model_type, forecast_date, predicted_value, confidence_interval`

**D_POLICY_QA**（政策问答）  
`id, question, answer_text, source_articles(JSON), confidence, user_feedback`

### 5.3 ER 关系

```
D_METRIC 1───N D_REPORT 通过引用
D_REPORT 1───N D_REPORT_INSTANCE
D_SCREEN 1───N WIDGET 引用 D_METRIC
USER 1───N D_SUBSCRIPTION N───1 D_REPORT
```

## 6. 数据流与关键流程

### 6.1 ETL 流程

```
业务库 → CDC/日志 → Kafka → Flink → ODS (每日 02:00) → DWD → DWS → ADS (04:00) → 报表刷新
                                                        ↓
                                              数据质量检查
                                              (完整率/一致率/异常值)
```

### 6.2 大屏渲染流程

前端加载 → 请求 `/api/dash/board?params` → 服务端从 ADS 层查询 → 缓存 5 分钟 → 返回 JSON → ECharts 渲染。  
关键指标支持点击下钻：ADS → DWS → DWD → 业务表。

### 6.3 自然语言查询

用户输入 → LLM 解析意图 + 匹配指标字典 → 生成 SQL → 权限过滤 → 执行 → 结果可视化 → 反馈收集。

## 7. 界面与交互原型

### 7.1 管理驾驶舱（登录后默认页）

不同角色看到不同布局：  
- **院所领导版**：核心 KPI 卡片 + 趋势曲线 + 风险预警 + 今日重要事件  
- **科研管理员版**：待办审批 + 数据变更 + 报表快捷入口  
- **PI 版**：我的项目/成果/经费概览  
- **财务版**：到账/支出/异常  
- **审计版**：追溯查询入口 + 关注事项

### 7.2 报表设计器

拖拽式：左侧字段树（按业务域分类），中间画布，右侧属性面板。  
支持透视表、折线、柱状、饼、地图、雷达、桑基、关系图。  
支持参数化（时间、部门、类型）。  
一键保存为"我的模板"或发布全院。

### 7.3 数据大屏 `/dash/screen`

全屏深色背景，多块拼图布局；支持自动轮播 6 组视图；适合会议室 4K 大屏展示。  
预置模板：科研全景 / 经费监督 / 成果转化 / 人才队伍 / 学科分布。

### 7.4 AI 政策问答

对话框形式，用户提问 → 检索政策库（RAG） → LLM 组织回答 → 附条款出处链接。  
可上传文件问："这份合同有什么问题？"

### 7.5 机构间对标

雷达图：本院 vs 选定 N 家同类院所，多维度对比（项目/经费/成果/人才/转化）。  
数据源：公开数据 + 上级单位年报。

### 7.6 报送模板管理

预置：教育部科技统计年报 / 科技部统计年报 / 中科院年度评价 / 省科技厅年度报表。  
一键生成 → 审核 → 导出（Excel/PDF/XML 报文） → 报送留痕。

### 7.7 审计追溯页

任意报表可下钻到明细 → 明细可下钻到审批链 → 审批链可下钻到操作日志 → 日志附完整上下文快照。

## 8. AI 能力详规

### 8.1 D-11 自然语言查询（NL2SQL）

**模型**：LLM + Schema-aware prompt + 指标字典。  
**约束**：  
- 只能查询当前用户权限范围内的表  
- 生成 SQL 前必经"语义回读"（"你是不是想问……"）  
- 结果附 SQL 可视化便于校验

**评估**：执行准确率 ≥ 75%，用户满意度 ≥ 4/5。

### 8.2 D-12 AI 政策问答助手

**语料**：国家/部/省/院所四级科研政策文件、批复、指引、条款解读。  
**处理**：RAG 检索 Top-5 相关条款 + LLM 组织回答。  
**输出**：答案 + 引用条款编号 + 原文跳转。  
**风险控制**：涉及具体金额、审批权限时，答案标注"请与科研办确认"。

### 8.3 D-13 AI 态势简报

**触发**：每月 1 号 08:00 自动生成，推送领导。  
**内容**：核心 KPI 环比 + 重大事件摘要 + 风险清单 + 建议关注点。  
**格式**：结构化图文 + PDF 附件。

### 8.4 D-16 趋势预测

**目标**：经费到账预测、论文产出预测、项目立项数预测。  
**模型**：Prophet + 外部指标（GDP、国家政策信号）。  
**展示**：预测曲线 + 置信区间 + 关键假设。

### 8.5 D-15 学科演化图谱

**基于**：历年论文关键词 + 专利 IPC 分类。  
**方法**：主题模型（BERTopic）+ 引文网络。  
**输出**：学科热度演化时间轴 + 交叉学科桥接。

## 10. 接口清单

- `GET /api/dash/metrics/{code}` 指标查询  
- `POST /api/dash/report/{id}/generate` 生成报表实例  
- `GET /api/dash/subscribe` 订阅管理

**内部事件**：
- `metric.threshold.breach` → 触发通知  
- `etl.completed` → 刷新缓存  
- `report.scheduled` → 定时生成

## 11. 异常处理与边界场景

- **数据延迟**：大屏顶部展示"数据截至日期"，T+1 未刷新时红色提醒。  
- **指标口径变化**：历史报表保留旧口径版本，新报表用新口径，标注变更说明。  
- **NL2SQL 幻觉**：无法映射时兜底"未理解，请联系管理员"，不瞎猜。  
- **查询超时**：5 秒未返回则中断，建议用户缩小范围。  
- **权限冲突**：NL2SQL 生成的 SQL 必须先经权限改写层注入过滤条件。  
- **报送数据不一致**：不同报表间口径冲突时，以指标字典为唯一真源。  
- **数据质量下降**：ETL 检查失败告警，报表顶部标"数据存在部分缺失"。

## 12. 验收标准与非功能需求

**功能**：  
- 指标字典覆盖 60+ 项核心指标  
- 预置 20+ 常用报表 + 5+ 大屏模板 + 4+ 上级报送模板  
- NL2SQL 覆盖常见查询 75%  
- 政策问答准确率 ≥ 85%

**性能**：  
- 驾驶舱加载 < 1.5s  
- 大屏渲染 60 FPS  
- 常规报表 5 秒内返回  
- NL2SQL 端到端 < 5s  
- 数据新鲜度 T+1（每日凌晨 4 点前完成）

**可用性**：  
- 大屏支持自动轮播、断点续播  
- 报表导出支持 CSV/Excel/PDF  
- 邮件订阅、企业微信推送、站内消息三通道

**数据治理**：  
- 指标命名统一，避免口径歧义  
- 所有报表标注数据源、生成时间、责任部门  
- 建立指标变更评审流程
