# 07 · 人员与团队 PRD

**模块代号**：S（Staff）  
**优先级**：M1 · P0  
**依赖模块**：HR 系统对接 · 04 成果管理 · 02 项目过程 · 画像引擎 · AI 中台

---

## 1. 模块概述与目标

管理科研院所所有参与科研活动的人员档案与团队结构：正式研究人员、博士后、访问学者、客座研究人员、研究生、临时聘用人员。**核心目标是让人员不再是孤立的档案，而是与项目、经费、成果深度关联的"科研画像"实体**。

**目标**：科研人员档案 100% 覆盖；PI 画像自动化生成；跨机构学者流动 0 断档。

## 3. 用户故事（节选，共 22 条）

- **S-USR-01** (P0)：作为科研人员，我的基本信息（姓名/工号/部门/入职）从 HR 系统自动同步，我只需补充科研相关内容（ORCID、研究方向、学术任职）。
- **S-USR-02** (P0)：作为 PI，我能在系统里组建我的创新团队，添加成员并记录每个人的贡献。
- **S-USR-03** (P0)：作为管理员，PI 离职时系统能强制要求交接其名下项目与经费。
- **S-USR-05** (P0)：作为科研人员，我跳槽到其他院所时，历史成果保留在原单位，个人账号可跨机构关联。
- **S-USR-06** (P1)：作为院所领导，我能看到任一 PI 的画像——项目、成果、影响、合作网络、人才培养。
- **S-USR-08** (P0)：作为管理员，我能为访问学者设置短期权限（1 年到期自动失效）。
- **S-USR-10** (P1)：作为管理员，AI 能帮我识别学科方向人才梯队缺口。

## 5. 数据模型

### 5.1 主要表

**S_STAFF**（科研人员主表，从 HR 同步 + 扩展字段）  
`id, user_id, hr_code, name, name_en, gender, birth_year, id_card_hash, email, phone, department_id, position(研究员/副研/助研/博后/客座/学生), title(职称), education, hire_date, leave_date, employment_status(在职/离职/退休/访问/客座), photo_url, orcid, wos_researcher_id, scopus_id, cnki_author_id, bio, research_expertise(JSON tags), external_appointments(JSON), is_pi`

**S_TEAM**（团队/课题组）  
`id, name, code, type(创新团队/PI 组/课题组/重点实验室), pi_user_id, member_ids(JSON [{user_id, role, joined_at, left_at}]), formed_date, evaluation_cycle, status`

**S_MEMBERSHIP**（成员关系）  
`id, team_id, user_id, role(LEADER/CORE/MEMBER/STUDENT/VISITOR), joined_at, left_at, contribution_summary`

**S_VISITOR**（客座/访问学者）  
`id, staff_id, host_pi_id, host_team_id, home_institution, visit_type(短期/长期/合作研究), start_date, end_date, funding_source, project_id, permissions_scope(JSON)`

**S_STUDENT**（学生）  
`id, staff_id, student_type(博/硕/本科毕设), supervisor_user_id, enroll_year, graduate_year, thesis_topic, associated_project_ids(JSON)`

**S_PLEDGE_HISTORY**  
（在模块 06 中定义）

**S_PORTRAIT**（PI 画像，日/周切）  
`id, staff_id, snapshot_date, project_count_total, project_count_active, funding_total, funding_yearly, output_count_papers, output_count_patents, h_index, total_citations, top_journals(JSON), expertise_tags(JSON AI 生成), collaboration_score, mentoring_count, career_stage(上升/稳定/成熟)`

**S_COLLAB_GRAPH**（合作关系边表）  
`id, staff_a_id, staff_b_id, weight(合作次数), first_year, last_year, shared_projects(JSON), shared_papers(JSON)`

**S_TALENT_PLAN**（人才计划称号）  
`id, staff_id, plan_name(杰青/优青/长江/万人/院所自立), level, awarded_year, duration_years, status`

## 6. 业务流程与状态机

### 6.1 人员异动流程

```mermaid
flowchart LR
  A[HR 触发离职] --> B[系统标记状态]
  B --> C{是否 PI?}
  C -- 是 --> D[项目交接流程]
  D --> E[经费冻结/移交]
  E --> F[权限降级为"离职可见本人"]
  C -- 否 --> F
  F --> G[团队/学生改派导师]
  G --> H[归档保留]
```

### 6.2 客座学者入驻

申请 → 审批 → 开通账号 → 分配权限范围（限本项目/本团队） → 到期前 30/7 天提醒 → 到期自动失效。

### 6.3 团队生命周期

组建 → 运行 → 周期评估 → 变更（增删成员） → 解散/换届。

## 7. 界面与交互原型

### 7.1 我的档案 `/staff/me`

标签页：基本 · 科研（方向/代表作） · 项目 · 成果 · 团队 · 荣誉 · 承诺记录 · 权限。  
一键"AI 生成简历"：从画像导出 PDF 学术简历。

### 7.2 人员总览（管理员）

列表 + 组织树 + 卡片。可按部门/类型/方向/关键词筛选。  
批量导入/导出，异动操作面板。

### 7.3 团队管理 `/staff/team`

组织架构图（vis.js 力导或树状），团队成员列表 + 加入/退出时间轴。  
团队年度评估入口。

### 7.4 PI 画像页 `/staff/{id}/portrait`

**雷达图**：项目数 / 经费 / 成果 / 影响 / 合作 / 培养 六维。  
**时间轴**：历年项目、成果、称号。  
**合作网络图**：与该 PI 有过合作的所有学者，节点大小=合作次数，颜色=所属机构。  
**AI 摘要**："该 PI 处于成熟期，方向集中在 XX，与 A、B、C 三位学者合作紧密，近 3 年引用增长 25%……"  
**代表性成果 Top 10**。

### 7.5 客座学者申请页

表单 + 上传材料 + 邀请人 + 项目关联 + 期限。审批后自动开通账号 + 授权。

## 8. AI 能力详规

### 8.1 S-05 AI 研究方向标签生成

**输入**：学者历史论文标题+摘要+专利文本。  
**处理**：LLM 抽取主题关键词 + 与预设学科体系对齐（arXiv 分类/中图分类）。  
**输出**：5-10 个标签 + 权重。  
**触发**：新成果入库时增量更新，每季度全量刷新。

### 8.2 S-13 PI 画像

**聚合数据源**：项目、经费、成果、引用、合作、承诺、诚信。  
**AI 摘要**：LLM 生成自然语言"学者简介"，辅助评审/合作决策。  
**画像更新**：每周批量刷新；关键事件（新成果/新项目/新称号）触发即时更新。

### 8.3 S-14 合作关系网络

**构建**：从论文作者共现、项目成员共现、专利发明人共现聚合。  
**分析**：中心度、社团检测、跨机构桥接者。  
**可视化**：力导向图，支持按时间切片。

### 8.4 S-15 AI 人才梯队分析

**输入**：全院学者画像 + 退休时间表 + 战略方向。  
**输出**：各方向的年龄分布、后备人才缺口、招聘建议。

## 10. 接口清单

**外部**：
- HR API（北森/SAP/用友）  
- CAS/LDAP 单点登录  
- ORCID API  
- 微信企业号（人员同步）

**内部事件**：
- `staff.onboarded` → 触发承诺签署流程

- `staff.portrait.updated` → 更新数据大屏  
- `staff.permissions.expired` → 自动降级

## 11. 异常处理与边界场景

- **同名同姓学者**：以工号 + ORCID 双主键区分。  
- **跨机构合作**：外部学者不入本院 S_STAFF 主表，走 EXPERT 表。  
- **人事变更未同步**：定时对账 + 手动纠错入口。  
- **PI 突然离职**：项目在未交接前经费冻结。  
- **退休返聘**：employment_status 支持"返聘"，权限按新身份。  
- **双聘**：支持一人多部门，主部门唯一，跨部门贡献可分配。

## 12. 验收标准与非功能需求

**功能**：  
- 与主流 HR 系统对接（至少 2 家）  
- 画像生成覆盖全院 PI 100%  
- 客座学者权限到期自动失效 100%

**性能**：  
- 人员列表 5000 人 < 500ms  
- 画像批量刷新 < 30 min（5000 人）  
- 关系网络图 < 2000 节点可流畅渲染

**合规**：  
- 敏感字段加密落库  
- GDPR/个保法合规，学者可申请查看/删除非法定保留数据

**数据保留**：离职人员档案保留 15 年（可查询不可编辑）。
